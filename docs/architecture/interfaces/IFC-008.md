### IFC-008 — The test-run result artifact

**Status**: accepted
**As-built**: **built, 2026-09-05 (TASK-608)**. Producer: `app/tools/lib/results.py`
(`build_document()` / `write_artifact()`, emitted from `print_results`); schema, reader and
staleness guard: `app/tools/lib/artifact.py`. All three summary-text parsers are retired — see the
Enforcement table. TASK-624 landed the closed enum and the typed gating this builds on.

**Parties**: the results layer (`app/tools/lib/results.py`, `app/tools/suite/serialdbg/runner.py`) ↔
every gate and consumer (`run/player-gate`, `run/test`, `run/test-targeted`, `run/test-sync`,
`run/wr-gate`, and any host tool reporting on a run)
**Transport**: a JSON file written once per run, at a path the run reports
**Protocol**: schema-versioned document; additive-only within a major version
**Direction**: producer → consumers, one-way, after the run

---

**Why it must exist.** The human summary is not a contract and has already been read as one, wrongly.
`results.py` writes `FLAKY-PASS`; `run/player-gate`'s regex matched `FLAKE`; the line was dropped, the
cell scored `MISSING`, and the gate printed **REGRESS** for a firmware regression that never happened
— with the *unresolved* flake parsing and the *resolved* one not
([M-TESTARCH precedence](../designs/M-TESTARCH-precedence-hierarchy.md) §4.1; fixed as TASK-573).
Three consumers parse that text today. ADR-066 D1 makes the artifact the sole machine interface and
retires all three.

**Content**

| Group | Fields | Notes |
|---|---|---|
| schema | version | additive-only within a major; a removal is a major bump |
| premise | build identity (ELF hash + env name), board identity, class order in force, id set selected and the reason it was selected, start/end time | ADR-066 D3; the build identity is the same value ADR-067 D1's refusal reads |
| per-id | id, verdict (closed enum), class, scope, effect, elapsed, and the verdict's structured reason | `effect` is consumed by R14/R17/R19 — see TASK-619's answer on the board |
| per-class | elapsed, counts by verdict | R53's measurement, folded in here rather than carried as a budget table |
| run | exit code, counts by verdict, the `UNMET` and `NOT-RUN` blocks in full | |

**The verdict enum is closed**: `PASS`, `FAIL`, `SKIP`, `FLAKY-PASS`, `FLAKE`, `NOT-RUN`, `UNMET`.

**Invariants**

- **I1 — a gate matches an enum member, never a string prefix.** `app/tools/suite/serialdbg/_gate.py:129`'s
  `RESULTS.get(tid, "").startswith("FAIL")` is the shape this replaces.
- **I2 — only the results layer writes a verdict.** A suite body may not.
- **I3 — `UNMET` and `NOT-RUN` are distinct and the distinction is load-bearing.** `NOT-RUN` was
  never dispatched, because an earlier **class** failure blocked it, and always carries
  `blocked_by=<class>/<id>`. `UNMET` was dispatched but its **own premise** was not established, so it
  asserted nothing, and it frequently has no class failure to blame. Collapsing them loses
  attribution; ADR-066 D2.
- **I4 — `UNMET` blocks, and its exit code is 1** unless a class failure already set 3 or 4 by
  precedence. `UNMET` owns no exit code of its own, exactly as `NOT-RUN` owns none. The full
  justification is ADR-066 D4 and is not restated here.
- **I5 — the exit code is a coarse signal.** Anything that must distinguish `UNMET` from `FAIL` reads
  this artifact. The code exists so a shell `if` can tell clean from not-clean.
- **I6 — the human summary is not an interface** and no consumer parses it. A run may print anything
  it likes for a reader.
- **I7 — a verdict carries a structured reason, not prose** (R32), so reasons can be grouped and
  counted rather than eyeballed.

**Enforcement**

| Invariant | Enforcement | Strength |
|---|---|---|
| I1, I2 | typed gating (TASK-624: `Verdict`, `verdict_of()`, `classify()` raising `UnknownVerdict`) | **built** |
| I3, I4 | `check_verdict_invariants()` (biconditional, run on every summary) + the `UNMET` arms of `run/player-gate --selftest` | **built** |
| I6 | all three parsers retired (TASK-608); `app/tools/test_run_artifact.py` `T_ART_50` re-counts them over `app/tools/` and `run/` at every `run/check`, acceptance number **0** | **built, blocking at zero** |
| staleness | the run nonce (`RESULTS_RUN_TOKEN`), refused as `StaleArtifact`; arms `T_ART_10`-`T_ART_15` and the `--selftest` reader arms | **built** |

**Decided by TASK-608**

1. **Path and lifetime — one file per run, uniquely named, never overwritten.** Default
   `app/tools/.runs/run-<UTC>-<pid>-<token8>.json` (gitignored); a consumer that needs a known path
   exports `RESULTS_JSON` and owns the file's lifetime. There is deliberately **no `latest.json`
   and no symlink**: a stable name is exactly what a consumer reads without noticing it did not
   change. Staleness is guarded in three layers — unique default path, the `RESULTS_RUN_TOKEN`
   nonce echoed in the document and checked by `load(expect_token=…)`, and a reader that refuses a
   missing file or an unknown schema MAJOR rather than yielding an empty result set.
2. **How a multi-leg gate composes two artifacts** — `run/player-gate` reads one artifact **per
   leg**, with a per-leg nonce, into the per-leg `.results` file its comparator already consumed.
   Composition is unchanged; only the extraction moved. A cross-leg composition rule is still not
   specified here, because the gate does not have one.

**Still not decided** (flagged, not filled in)

3. **Whether the schema is shared with the flake registry and the test-meta records**, or merely
   references them by id. As built it **references**: the flake registry by content hash
   (`premise.flake_registry_sha256`), the test-meta record by copying `cls`/`scope`/`effect` onto
   each row. Copying is a mirror in the LL-114 sense and is a live question for @Architect.

**Version**: **1.0** (`schema.name = esp_spotify.test-run`). MAJOR.MINOR; additive-only within a
MAJOR — a new field is a MINOR bump and old readers keep working, a removal or a re-meaning is a
MAJOR bump and `load()` refuses it outright.
**Defined by**: ADR-066 · [M-TESTARCH precedence](../designs/M-TESTARCH-precedence-hierarchy.md) §4
(the exit-code allocation), §4.1 (why a new code is not free) · TASK-573 (the false REGRESS this
exists to prevent) · TASK-566 (`NOT-RUN`)
**Test ids**: `run/player-gate --selftest`'s cases, which are the gate's own negative tests (BP-068)
