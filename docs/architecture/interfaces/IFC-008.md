### IFC-008 — The test-run result artifact

**Status**: accepted
**As-built**: **built, 2026-09-05 (TASK-608)**; premise completed 2026-09-06 (TASK-645, schema 1.2). Producer: `app/tools/lib/results.py`
(`build_document()` / `write_artifact()`, emitted from `print_results`); schema, reader and
staleness guard: `app/tools/lib/artifact.py`. All three summary-text parsers are retired — see the
Enforcement table. TASK-624 landed the closed enum and the typed gating this builds on.

**Parties**: the results layer (`app/tools/lib/results.py`, `app/tools/suite/serialdbg/runner.py`) ↔
every gate and consumer (`run/player-gate`, `run/test`, `run/test-targeted`, `run/test-sync`,
`run/wr-gate`, and any host tool reporting on a run)
**Transport**: a JSON file written once per run, at a path the run reports
**Protocol**: schema-versioned document; additive-only within a major version
**Direction**: producer → consumers, one-way, after the run

---

**Why it must exist.** The human summary is not a contract and has already been read as one, wrongly.
`results.py` writes `FLAKY-PASS`; `run/player-gate`'s regex matched `FLAKE`; the line was dropped, the
cell scored `MISSING`, and the gate printed **REGRESS** for a firmware regression that never happened
— with the *unresolved* flake parsing and the *resolved* one not
([M-TESTARCH precedence](../designs/M-TESTARCH-precedence-hierarchy.md) §4.1; fixed as TASK-573).
Three consumers parse that text today. ADR-066 D1 makes the artifact the sole machine interface and
retires all three.

**Content**

| Group | Fields | Notes |
|---|---|---|
| schema | version | additive-only within a major; a removal is a major bump |
| premise | build identity (ELF hash + env name), **harness identity**, board identity, class order in force, id set selected and the reason it was selected, start/end time | ADR-066 D3; the build identity is the same value ADR-067 D1's refusal reads. `harness_version`/`harness` and `board` were filled in by TASK-645 — see "Decided by TASK-645" below |
| per-id | id, verdict (closed enum), class, scope, effect, elapsed, and the verdict's structured reason | `effect` is consumed by R14/R17/R19 — see TASK-619's answer on the board |
| per-class | elapsed, counts by verdict | R53's measurement, folded in here rather than carried as a budget table |
| run | exit code, counts by verdict, the `UNMET` and `NOT-RUN` blocks in full | |

**The verdict enum is closed**: `PASS`, `FAIL`, `SKIP`, `FLAKY-PASS`, `FLAKE`, `NOT-RUN`, `UNMET`.

**Invariants**

- **I1 — a gate matches an enum member, never a string prefix.** `app/tools/suite/serialdbg/_gate.py:129`'s
  `RESULTS.get(tid, "").startswith("FAIL")` is the shape this replaces.
- **I2 — only the results layer writes a verdict.** A suite body may not.
- **I3 — `UNMET` and `NOT-RUN` are distinct and the distinction is load-bearing.** `NOT-RUN` was
  never dispatched, because an earlier **class** failure blocked it, and always carries
  `blocked_by=<class>/<id>`. `UNMET` was dispatched but its **own premise** was not established, so it
  asserted nothing, and it frequently has no class failure to blame. Collapsing them loses
  attribution; ADR-066 D2.
- **I4 — `UNMET` blocks, and its exit code is 1** unless a class failure already set 3 or 4 by
  precedence. `UNMET` owns no exit code of its own, exactly as `NOT-RUN` owns none. The full
  justification is ADR-066 D4 and is not restated here.
- **I5 — the exit code is a coarse signal.** Anything that must distinguish `UNMET` from `FAIL` reads
  this artifact. The code exists so a shell `if` can tell clean from not-clean.
- **I6 — the human summary is not an interface** and no consumer parses it. A run may print anything
  it likes for a reader.
- **I7 — a verdict carries a structured reason, not prose** (R32), so reasons can be grouped and
  counted rather than eyeballed.
- **I8 — one artifact describes exactly one run, and artifacts are never merged.** A consumer holding
  two or more artifacts reads each one separately and keys everything it derives by
  `(artifact, id)`. Flattening two documents into a single id→verdict map is forbidden: ids legitimately
  recur across runs (`run/player-gate` declares `T_PMT_00/03/04` on **both** legs), so a merge
  silently overwrites one leg's verdict with the other's and the loser disappears with no error.
  Cross-run composition is the consumer's, per D-COMP below.
- **I9 — the per-id `cls`/`scope`/`effect` copy is a SNAPSHOT, not a mirror.** It records what the
  test-meta record said *at the moment of this run*, which is what makes the document a premise. It
  is never read as current truth. See D-SNAP below for the rule and its one guard.

**Decided by TASK-608**

1. **Path and lifetime — one file per run, uniquely named, never overwritten.** Default
   `app/tools/.runs/run-<UTC>-<pid>-<token8>.json` (gitignored); a consumer that needs a known path
   exports `RESULTS_JSON` and owns the file's lifetime. There is deliberately **no `latest.json`
   and no symlink**: a stable name is exactly what a consumer reads without noticing it did not
   change. Staleness is guarded in three layers — unique default path, the `RESULTS_RUN_TOKEN`
   nonce echoed in the document and checked by `load(expect_token=…)`, and a reader that refuses a
   missing file or an unknown schema MAJOR rather than yielding an empty result set.
2. **How a multi-leg gate composes two artifacts** — `run/player-gate` reads one artifact **per
   leg**, with a per-leg nonce, into the per-leg `.results` file its comparator already consumed.
   Composition is unchanged; only the extraction moved. **A cross-leg composition rule is not
   specified here and never will be — see D-COMP below (@Architect, TASK-644).** What the gate does
   as built is exactly what I8 requires.

**Decided by @Architect, 2026-09-06 (TASK-644)** — the three specification gaps TASK-608/624/645
flagged rather than filled. All three **confirm the as-built behaviour**; no landed code is
invalidated by any of them.

**D-COMP — cross-leg / cross-run composition is the CONSUMER's, and deliberately not this
interface's.** TASK-608 recorded "a cross-leg composition rule is still not specified here, because
the gate does not have one". That is now a decision rather than an omission: **this interface will
not grow one.**

*Why.* An artifact is the record of **one** run. Composition is a judgement about what several runs
*mean together*, and that judgement is different for every consumer: `run/player-gate`'s two legs are
two different firmware builds scored against a **pre-declared per-leg pass set** keyed `(leg, id,
expected)`, and its verdict is "did any declared cell regress"; the R21 shuffle job's two runs are the
**same** build in two orders and its verdict is "did any id change value"; `run/wr-gate`'s trials are
n runs of one build and its verdict is a **rate**. Those three compositions share no operator. A rule
in the interface would either be one of them wearing a general name — which is how a comparator's
policy becomes an unremovable schema commitment — or so weak it says nothing.

What the interface **does** owe composition is the safety property, and that is **I8**: read one
artifact per run, with that run's own nonce, and key by `(artifact, id)`. `run/player-gate` already
satisfies I8 as built — one artifact per leg, one nonce per leg, extracted into the per-leg
`.results` file its comparator already consumed. A consumer that wants composition writes it, names
it, and owns it.

**D-SNAP — copying `cls`/`scope`/`effect` onto each row is a SNAPSHOT, and snapshots are correct
here.** LL-114's failure class is a host tool encoding firmware truth **by copy** and then being read
*as current truth* — the taskbar mirror was stale, and `preview_layout.py --export` would have
written the stale value back. The distinguishing test is not "is it a copy" but:

> **Is anything going to read this copy as the current value?** If yes it is a **mirror** and LL-114
> applies. If it is only ever read as a dated record of something that already happened, it is a
> **snapshot**, and the copy is the point.

The artifact is written once, never edited, and never consulted for what a test's class *is now* —
`_meta.py` is re-read from source on every run and is the only source. Referencing the meta record by
id instead would be **worse, not better**: re-classify a test next month and every archived artifact
would silently re-interpret under the new taxonomy, so a run that was gated by CORE would read as
having been gated by FEATURE. A premise that changes after the fact is not a premise. The same
reasoning is why `premise.flake_registry_sha256` is a **content hash** and not a path.

*The one guard, and it is the whole risk.* A snapshot becomes a mirror the instant something reads it
forward. **No tool may reconstruct, regenerate, diff-as-authority, or validate `_meta.py` from an
artifact**; the arrow is source → artifact and never back. Any future tool that wants to compare an
artifact's `cls` against today's meta must report it as *"the taxonomy changed since this run"*, never
as *"the artifact is wrong"*.

**D-VER — correcting a field to the value its contract always specified is a MINOR, and MUST still
bump.** The general rule, not TASK-645's instance:

1. **A defect fix that brings a field to the value its contract already specified is a MINOR.** The
   version numbers the **contract**, not the producer's fidelity to it. A reader written to the
   contract keeps working; a reader written to the observed-buggy behaviour was never a conformant
   reader and this version field owes it nothing.
2. **It MUST bump anyway**, even though nothing was added. This is the load-bearing half. Archived
   artifacts on disk still carry the wrong value, and after a silent fix **nothing distinguishes a
   pre-fix document from a post-fix one** — a consumer reading a year of runs would have no way to
   know which side of the correction each sits on. The bump *is* the discriminator, and the correction
   MUST be recorded against the version it landed in.
3. **Two exceptions force a MAJOR.** (a) The contract was ambiguous enough that the old behaviour was
   a defensible reading — then the fix is a **re-meaning**, not a correction, and the ambiguity gets
   fixed in this document in the same change. (b) The correction **narrows the field's domain**, so a
   value a conformant reader previously had to accept is now refused.

**TASK-645's MINOR (1.1 → 1.2) is CONFIRMED — but not for the reason it gave.** It justified MINOR by
measuring that `premise.*` has zero consumers outside the producer. That is a **headcount, not a
rule**: it will not be true the next time, and a version policy that depends on how popular a field is
this week is not a policy. The bump is right under (1) and mandatory under (2), and the consumer count
is irrelevant to both.

**Decided by TASK-645** (the three premise gaps TASK-608 flagged rather than filled)

1. **"harness version" (R30) is a CONTENT HASH over the harness source**, not a git description:
   `premise.harness_version = "src-<12 hex>"` from `app/tools/lib/version.py`, over
   `app/tools/**/*.py` + `run/*`, with the full digest, the file count, and the git commit/describe/
   dirty flag carried alongside under `premise.harness` as **provenance only**. Git is not the
   identity because this project works on master directly: the tree is uncommitted most of the
   working day, so `--dirty` would mark nearly every run and separate none of them from each other.
   The hash needs no `.git`, no network and no build, and costs ~19 ms once per run.
2. **"the board" (ADR-066 D3) is the factory efuse MAC**, read once at session setup beside the ELF
   identity via the new `get boardId` debug key (additive per ADR-065 D4). `premise.board` is
   `{id, id_source, transport{port, baud}}`: the port is demoted to transport, because a USB
   re-enumeration renames it on the same board and a second board on the freed node inherits it.
   Firmware that does not answer leaves `id: null` with a NAMED `id_source` (`absent`, `malformed`,
   `unanswered:<exc>`) — never back-filled from the port.
3. **`run/dut-health` emits an artifact.** It exited three lines before `print_results`, so the one
   entry point whose whole job is to say whether the board is a valid subject was the only one that
   said it in prose alone. Its 0/3/4 contract is unchanged; a broken record (an I2/I3 violation)
   now surfaces as exit 1 rather than as a fit board.

**Decided by TASK-677** (schema 1.3, additive/optional; not previously logged in this doc — see
`lib/artifact.py`'s own version-history comment, which is the fuller record): `run.rig`, the
host+DUT fault-correlation summary (R/U/bod_trips/W per PROP-011 §4) for the run's window, present
only when `RIGWATCH=1`.

**Decided by TASK-636** (schema 1.4, additive/optional, R20/R21) — `premise.shuffle_seed`: the seed
passed to `runner.py --shuffle-family SEED`, `null` on every run that did not pass it. No new field
was needed for the EXECUTED (post-shuffle) order itself: `premise.class_order` already records the
sequence ids actually ran in for every run (`_gate.EXECUTED_ORDER`, set unconditionally by
`run_suite()`), not only a `--class-order` one — the name predates this use but the semantics already
covered it. The cross-run comparison this feeds — `lib/artifact.py`'s `order_dependence()` — is a NEW
CONSUMER of this interface, not a change to it: **`ORDER-DEPENDENT` is not a verdict and is not a
field anywhere in this schema** (ADR-066 D2a). It is a label the comparison itself prints, over two
or more ordinary seven-verdict documents, keyed by id and naming both runs' executed positions.

**Version**: **1.4** (`schema.name = esp_spotify.test-run`). MAJOR.MINOR; additive-only within a
MAJOR — a new field is a MINOR bump and old readers keep working, a removal or a re-meaning is a
MAJOR bump and `load()` refuses it outright. **A field CORRECTED to the value its contract always
specified is a MINOR and MUST still bump — D-VER.**

exists to prevent) · TASK-566 (`NOT-RUN`)
