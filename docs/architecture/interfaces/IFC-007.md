### IFC-007 — Serial debug console (the DUT test surface)

**Status**: proposed
**As-built**: the surface has shipped for a year and is unversioned; this document contracts it for
the first time. What is marked **open** below is not yet decided and must not be assumed.

**Parties**: host test tooling (`app/tools/lib/dut.py`, `app/tools/suite/serialdbg/**`, the four
independent `SerialDut` harnesses, `run/*` scripts) ↔ firmware serial console
(`app/src/debug/serialConsole/`)
**Transport**: UART over USB-CDC (CH340), 115 200 baud, newline-framed text
**Protocol**: one-line request, one-line JSON reply. `get <key> [args]`, `set <key> <val>`,
`tap x y`, `drag …`, `switchApp <id>`, plus command verbs (`screendump`, `colorprobe`, …)
**Direction**: host → device for commands; device → host for replies, and — permitted but not yet
shipped — for unsolicited event lines (ADR-065 D3)

**Defined in code by**: `app/src/debug/serialConsole/` (`cmdGet.cpp`, `cmdSet.cpp`, `cmdMisc.cpp`
and siblings). The key list is **generated, not mirrored**: `app/tools/gen/gen_get_keys.py`.

**Compiled in only under `SERIAL_DEBUG`.** No production build carries any of this (ADR-061).

---

**Why it must exist.** `architecture.md:106-107` calls this "the DUT test surface for the whole VE
suite" and [M-TESTARCH](../designs/M-TESTARCH-test-architecture.md) §4 I1 calls it "a contract, not a
debug aid" — asserting that "every `get` reply is a versioned, additive-only JSON object". That
assertion has been quoted as already true while shipped code violates it: `get wifiCfg`
(`app/src/debug/serialConsole/cmdGet.cpp:202-214`) prints a bare bracket line and then a JSON ack
with no fields, and `Dut.read_json()` discards every line not starting with `{`
(`app/tools/lib/dut.py:1086`) — so the one command that distinguishes TASK-426's dead-SSID wedge from
an absent AP is mute to the harness. This is the largest seam in the system, it had no IFC number,
and IFC-004/005/006 are reserved stubs for smaller things.

**Message shape**

| Type | ID | Payload | Description |
|---|---|---|---|
| `get <key>` | C1 | key + optional positional args | one JSON reply object |
| `set <key> <val>` | C2 | key + value | JSON ack |
| `tap x y` / `drag …` | C3 | canvas coords | JSON ack; input injection |
| `switchApp <id>` | C4 | app id | JSON ack |
| command verb | C5 | verb-specific | may emit a multi-line stream (`screendump`) before its ack |
| reply | R1 | JSON object, one line, `"last":true` terminator convention | the only thing a host may parse |
| event line | R2 | JSON object with an explicit event marker | **permitted, not yet shipped** — ADR-065 D3 |

**Invariants**

- **I1 — additive only. No renames, ever.** A key or a reply field may be added; neither may be
  removed or renamed without a gate exception carrying an owner and a date. Renaming breaks tests
  silently, months later, on hardware. (BP-024, generalised from one command to the surface.)
- **I2 — the key list is generated from firmware, never hand-maintained.** `gen_get_keys.py` scans
  `.h/.hpp/.cpp/.cc` full-tree (`gen_get_keys.py:48`, TASK-600 — the count went 43 → 111 the day it
  stopped globbing headers only), and `run/check` compares the count. A contract enforced by a
  generator that cannot see half the firmware is not enforced.
- **I3 — a reply is one line and is a JSON object.** A payload that must exceed one line is a
  command verb's stream (C5), never a reply. *(The framing rule for streams is **open**.)*
- **I4 — correlation is optional and additive.** A caller may supply a sequence id; the reply echoes
  it only when supplied. A caller that supplies none gets today's reply byte for byte. ADR-065 D2.
- **I5 — a per-app key answers only while its owning app is active**, and is otherwise refused with a
  named error. ADR-063 D3. *(The error token itself is **open** — see below.)*
- **I6 — no unsolicited line ships until every consumer discards unknown ones safely.** The one-line
  request/response assumption is held by ~19 files and four separate `SerialDut` harnesses; R47's
  single-session-layer consolidation (TASK-599) is a precondition of any push key. ADR-065 D3(2).
- **I7 — the pushable key set is derived from the polling loops it replaces**, never authored.
- **I8 — a signature/readback command is on-demand only.** `get sig` and its kin are never called
  from a render path, never on a device timer, and never from a host polling loop. ADR-064 D2 —
  a violation, not a future option.

**Error handling**

- An unknown key is refused; the reply is still a JSON object. *(Vocabulary **open**.)*
- A command verb that allocates (e.g. `screendump`'s band buffer,
  `app/src/debug/serialConsole/cmdMisc.cpp:87`) must fail loudly rather than truncate, and must feed
  the TWDT during any multi-band loop (`app/src/debug/serialConsole/cmdMisc.cpp:106`; TWDT is 15 s,
  `panic=true`).
- A reply the host cannot parse is a **desync**, not a test failure. I4 exists so that this becomes
  detectable; until a call site opts in, it is not.

**Enforcement**

| Invariant | Enforcement | Strength |
|---|---|---|
| I1, I2 | `gen_get_keys.py` + the `run/check` count comparison | medium — landed TASK-600 |
| I3 | none today; `get wifiCfg` is a live violation | **none** |
| I4 | opt-in; the ratchet is the count of non-correlated call sites | none yet |
| I5 | one generated conformance row over `APP_ORDER` (TASK-637) | not yet built |
| I6, I7 | review, plus TASK-599 as a hard precondition | none yet |
| I8 | review; a periodic call site is an ADR-064 violation | none |

**Not yet decided** (recorded rather than guessed — ADR-065 D6)

1. **The version field.** The reply object has no version today. What it is called, when it
   increments, and whether it is per-key or per-surface.
2. **The refused-key error vocabulary.** I5's active-app refusal is its first client and needs a
   named token that a host can match on. Closed enum, additive-only, like every other vocabulary on
   this programme.
3. **Stream framing** for C5 command verbs (I3's carve-out).
4. **Whether `get wifiCfg`'s bracket-line payload is migrated into its JSON reply** — an I1-compatible
   addition, but it changes what a reader of the bracket line sees.

**Version**: none — contracted, not yet versioned. Item 1 above is what a `v1` needs.
