### IFC-003 — App lifecycle and shell dispatch

**Parties**: app shell (`loopTask`) ↔ each of the 13 `App` implementations
**Transport**: plain virtual function call, single-threaded on `loopTask`
**Protocol**: lifecycle callbacks + polled status predicates
**Direction**: shell → app for lifecycle and input; app → shell for status (polled, never pushed)

**Defined in code by**: `app/src/app.h`. Thirteen implementors — every `APP_X` row in
`appRegistry.h`.

---

**Message types**:

| Type | ID | Payload | Description |
|---|---|---|---|
| `init()` | L1 | — | first activation only, once per boot |
| `resume()` | L2 | — | every activation after the first |
| `suspend()` | L3 | — | leaving; the app is about to lose the screen |
| `tick()` | L4 | — | called every `loop()` while active |
| `handleInput(phase,x,y)` | L5 | `TouchPhase`, canvas coords | returns `true` if consumed |
| `hasPendingAsync()` | S1 | `bool` | async work from L5 still in flight |
| `hasError()` | S2 | `bool` | sustained error that will not self-heal |
| `isConnecting()` | S3 | `bool` | establishing, no result yet |
| `isNavigationTap(x,y)` | S4 | `bool` | this tap only navigates; starts no work |

**Lifecycle ordering** — as implemented in `switchApp()`:

```
switchApp(next):
  next == current           → return immediately (no-op, not an error)
  current->suspend()                                    L3 on the OLD app
  [screen wipe]
  currentAppId = next
  if !launched[next]:  launched[next] = true; next->init()    L1  ← XOR
  else:                                       next->resume()  L2  ← XOR
  renderTaskbar()
```

**Invariants**:

- **I1** — `init()` and `resume()` are **mutually exclusive** on any single activation. An app is
  never sent both in one transition. First activation gets `init()` only; every later one gets
  `resume()` only. An app needing shared setup calls its own helper from both.
- **I2** — `init()` fires **at most once per boot**, guarded by `g_appLaunched[]`.
- **I3** — `suspend()` is delivered to the **outgoing** app before `currentAppId` changes.
- **I4** — `tick()` and `handleInput()` are delivered **only to the active app**. A suspended app
  receives nothing and must not rely on background execution; work that must continue belongs to a
  task (IFC-002), not to an app.
- **I5** — all nine calls arrive on `loopTask` only. An app therefore inherits IFC-002's I2/I3: it may
  draw and touch SPIFFS freely, and must not be called from any other context.
- **I6** — status predicates S1–S4 are **polled after every `tick()`**, never pushed. They must be
  cheap, side-effect-free, and safe to call at any time including immediately after `init()`.
- **I7** — `hasError()` is **sticky and app-owned**: set on detection, cleared on the next success.
  The shell does no latching, so the state survives switching away and back (X019).
- **I8** — indicator precedence is **error > busy/connecting > idle**; `hasError()` wins over
  `isConnecting()` (ADR-046, X017).
- **I9** — the shell drops input while `hasPendingAsync()` is true, **except** where
  `isNavigationTap()` returns true. An app with in-app navigation during async work must override S4
  or its navigation taps are silently swallowed (TASK-384 — confirmed on hardware, not just in the
  harness).
- **I10** — an app must not construct with side effects. Anything order-dependent goes in `init()`,
  which the shell calls in a defined order. *(ADR-060 D5 — the composition root puts all thirteen
  instances in one translation unit, and that only stays safe while construction is trivial.)*

**Error handling**:

- **Unhandled input** — `handleInput()` returning `false` is normal; the shell then offers the tap to
  the taskbar/shell layer. Not an error.
- **An app that never clears `hasPendingAsync()`** wedges its own input permanently. There is no shell
  timeout on S1 — the shell's own `g_shellBusy` has a 3 s timeout, but S1 does not. This asymmetry is
  a known sharp edge.
- **An app throwing / hanging in `tick()`** starves every other context (IFC-002 I7). Apps must not
  block; long work goes to `dataTask` via IFC-001.
- **`switchApp()` to the current app** is a silent no-op, deliberately.

**Enforcement**:

| Invariant | Enforcement | Strength |
|---|---|---|
| I1, I2, I3 | structural — `switchApp()` is the only caller | strong |
| I5 | convention (IFC-002 G2 would assert it) | none |
| I6, I7, I8 | `run/check` smoke + `T242`/`T_TBFB_*` | medium |
| I9 | none — silent swallow is the failure mode | **none** |
| I10 | convention; verified once (no `App` subclass has a user-defined constructor) | none |

**Integration obligation**: a new app is not done when it compiles. See
`docs/architecture/designs/NEW-APP-CHECKLIST.md` — `hasPendingAsync()`, `tlsYield`/`tlsResume`,
`dbgGet`/`dbgSet`, and `cmdTap` busy propagation are the four that have been missed before.
