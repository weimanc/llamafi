### IFC-005 — PlaylistSource  *(RESERVED — NOT YET CONTRACTED)*

**Status**: proposed
**As-built**: Number reserved; contract not written.

**Parties**: `pleditView` renderer ↔ playlist providers (Spotify queue, WebRadio stations, local M3U)
**Transport**: plain function-call interface

**Why it must exist.** ADR-059 D4 decided "one PLEDIT renderer behind a `PlaylistSource` interface"
precisely so gesture and skin fixes land once. That is an interface by name in an ADR, with no
contract file — the failure mode the IFC layer exists to prevent. X055 records WebRadio's
independently-evolved PLEDIT copy being deleted in favour of it; X062 records the
`playOrder[]` / `viewOrder[]` disjointness that any provider must respect.

**What it must cover**: row count/text/selection accessors; the `playOrder` vs `viewOrder`
separation (shuffle permutes one, reorder the other, neither crosses); which operations may block
(none — IFC-002 I7); who owns row storage and for how long.

**Version**: none — stub
