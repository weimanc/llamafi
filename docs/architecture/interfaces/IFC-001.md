### IFC-001 — dataTask fetch service

**Parties**: apps / app shell (Arduino `loop()` context, + AppsSection validation flows) ↔ `dataTask` (pinned FreeRTOS task)
**Transport**: FreeRTOS request queue (in) + spinlock-guarded result slots (out); plain function-call API (`app/src/dataTask.h`)
**Protocol**: typed enqueue/poll pairs; request configs snapshotted at enqueue under `portMUX`; results copied into caller-supplied fixed structs; seq/epoch identity echoes for staleness discrimination
**Direction**: bidirectional (request → fetch → poll)

**Message types**:

| Type | Enqueue | Poll / result | Config transport | Identity |
|------|---------|---------------|------------------|----------|
| Weather | `enqueue(FetchType)` (→ `enqueueWeather(lat, lon)` per M-SETTINGS-WIRE2 G4) | `pollWeather(WeatherResult*)` | coords snapshot (G4) | none (single consumer) |
| Crypto | `enqueue(FetchType)` after `configureCrypto(ids, ccy)` | `pollCrypto(CryptoResult*)` + `lastCryptoHttpCode()` | pre-set config under mux | none |
| Stock quote | `enqueue` after `configureStockTickers(tickers[8][8])` | `pollStockQuote(StockQuoteResult*)` | pre-set config under mux | none |
| Stock chart | `enqueueStockChart(tickerIdx, rangeIdx)` / `enqueueStockChartBySym(sym, rangeIdx)` | `pollStockChart(StockChartResult*)` | request payload | **symbol echo** — consumer must strcmp `result.symbol` (TASK-300: stale parked result false-validated a typo ticker) |
| Heatmap | `enqueueHeatmapQuote()` | `pollHeatmapQuote(HeatmapQuoteResult*)` | — | none |
| Teletext | `enqueueTeletextPage(page, sub)` | `pollTeletext(TeletextState*)` + `lastTeletextHttpCode()` | request payload | page echo in state |
| WebRadio stations | `enqueueWebRadioStations(countryCC, bitrateCap)`; `abortWebRadioFetch()` cancels in-flight/queued (TASK-289) | `pollWebRadioStations(WebRadioStationsResult*)` | country+cap snapshot under mux | none (abort covers the race) |
| PlaneRadar | `enqueuePlaneRadar(lat, lon, distNm, epoch)` | `pollPlaneRadar(PlaneRadarResult*)` | coords snapshot under mux | **epoch echo** — consumer discards result.epoch < current (VE-PRL-6, location switch) |
| Geocode | `enqueueGeocode(countryCC, postcode)` → returns `seq` | `pollGeocode(GeocodeResult*)` | pending-config slot under mux (postcode > 8 chars — never the stock symbol payload, DEV-2) | **seq echo** — consumer stores enqueue's seq, ignores+discards mismatches (VE-PRL-5) |

Observability (lock-free reads, any core): `stockQuoteProgress()`,
`weatherFetchPhase()` / `cryptoFetchPhase()` / `stockChartProgress()` (-1 idle,
0=TLS 1=GET 2=parse); `get dataq` serial command discriminates never-enqueued /
never-dequeued / parked-in-tlsYield (TASK-299). Debug injection:
`debugInjectGeocode()` parks a synthetic result consumed by the next poll;
`enqueueGeocode()` is a no-op while parked (VE-PRL-2 isolation) — the template
for any future injected-result hook.

**Invariants**:

1. **dataTask is serial** — one fetch at a time; this is the mutual-exclusion
   argument that lets parse docs share one overlay region (mem_manifest).
2. **Enqueue is non-blocking and lossy** — drops silently when the queue is
   full; consumers own retry cadence (app tick timers), never spin.
3. **Config never read cross-core at fetch time** — everything the fetcher
   needs is snapshotted under mux at enqueue (or pre-set via `configure*`).
   Reading `g_settings` from the fetch path is a defect.
4. **Results are copies** — parse docs are pure scratch, freed/reused before
   the next fetch; every heap doc is registered in `app/mem_manifest.yaml`
   (LL-111; TASK-326 ruling for placed vs `placement: runtime`).
5. **New same-app consumers adopt an identity rule** (seq / epoch / symbol
   echo) whenever a stale in-flight result could land after consumer state
   changed — X026/X027 are the registered edges.
6. **`tlsYield()` before every handshake** (BP-031): Spotify's TLS context
   yields ref-counted; violations surface as SSL -32512 or WDT resets.
7. Poll functions are thread-safe (spinlock) and consume-on-read (`true` once
   per new result).

**Error handling**: `errorCode` per result struct — 0 = ok is **ambiguous**
(may mean "never fetched"); consumers gate on their own active-error state,
not on code==0. Positive = HTTP status; negative = HTTPClient errors, plus
project sentinels: -96 no-match (geocode), -97 parse-failed, -100 generic,
-101 heap guard, -120 CERT_VERIFY_FAILED (M-CERT-ERRCODE — pin rot fails
loudly). Decode via `httpErr()` (`logDecode.h`). PlaneRadar performs one
parse-error-only retry internally (TASK-313); no other fetcher retries —
callers re-enqueue on their own cadence. Malformed/lost requests: dropped
(invariant 2); out-of-order results: impossible (invariant 1) except stale
in-flight, handled by identity rules (invariant 5).
