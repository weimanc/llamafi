### IFC-002 — task-ownership and cross-context data exchange

**Status**: implemented
**As-built**: codifies the interface as already implemented in firmware (see `Version` below for the
contract's own revision history); TASK-534 added this line per BP-065, 2026-08-27 — no interface
change made
**Parties**: `loopTask` (Arduino) ↔ `spotifyTask` ↔ `dataTask` ↔ `wrAudio` pump task ↔
`arduino_events` (framework) ↔ WiFi driver task (framework, debug builds)
**Transport**: shared memory, five of the six contexts on one core — `portMUX` spinlocks, FreeRTOS
mutexes/queues, single-writer statics
**Protocol**: ownership-per-resource; four permitted crossing mechanisms (see Message types) — two
framework-created contexts currently cross by mechanisms outside this taxonomy; see M-CONCURRENCY §5
G6/G7 (TASK-544)
**Direction**: bidirectional, all pairs

**Worked out in**: [M-CONCURRENCY-task-ownership-contract.md](../designs/M-CONCURRENCY-task-ownership-contract.md)
— rationale, bug lineage and the cross-feature-matrix mining live there; this file is the obligation.

> model verbatim, including the same inverted `dataTask` stack figure and two drifted citations.

**Execution contexts** (measured, not assumed — four the project creates, two the framework creates
and the project registers a callback into):

| Context | Core | Prio | Stack | Created at |
|---|---|---|---|---|
| `loopTask` | 1 | 1 | 20 480 B | framework |
| `spotifyTask` | 1 | 1 | 10 240 B | `spotifyTaskStorage.cpp:591` |
| `dataTask` | 1 | 1 | 14 336 B (11 264 B iff `WEBRADIO_ONLY`) | `dataTaskStorage.cpp:1693` |
| `wrAudio` pump | 1 | **2** | 8 192 B | `audio/audioEngine.cpp:410` |
| `arduino_events` | 1 | **19** | 4 096 B | framework — see M-CONCURRENCY §1 |
| WiFi driver task | **0** | **23** | n/a | framework — closed-source `esp_wifi` internal |

**Five of the six are pinned to core 1; the WiFi driver task is not.** Among the five, there is no
true parallelism — they are time-sliced on one CPU, and every race among them is a **preemption**
race. The worst such edge is no longer the priority-2 pump task: `arduino_events` runs at priority
**19**, above every other core-1 context, in every build, and can preempt all four of the others at
any instruction. Code that is safe only because it is never preempted mid-sequence is safe **by
scheduling, not by construction** — changing a priority or a pinning invalidates it, and this project
already has an undocumented priority-19 context doing exactly that.

The WiFi driver task (core 0, debug builds only) is the one exception to "no true parallelism": it
runs genuinely concurrently with all five other contexts. Its `promiscCb` callback performs an
unlocked read-modify-write against a struct `loopTask` also reads unlocked — a true simultaneous
access for which the preemption-race framing above does not apply at all. See M-CONCURRENCY §1.1
and G6 (TASK-544).

**Message types** — the only permitted ways data crosses a context boundary:

| Type | ID | Payload | Description |
|---|---|---|---|
| Spinlock-published result | M1 | fixed struct, copied into caller storage | `portENTER_CRITICAL_SAFE` around publish and read; used for all `dataTask` results |
| Single-writer static | M2 | scalar | exactly one writing context, any number of readers; no lock (`vu::lLevelRef()`) |
| Mutex-guarded singleton | M3 | the resource itself | one hardware object behind one mutex (`s_wrAudioMutex` → `Audio`) |
| Post-request / poll-result | M4 | request struct + result enum | for anything that would block the caller (`wrPumpConnect`) |

Anything not M1–M4 is a contract violation, including "it's just a bool".

**Ownership**:

| Resource | Owner | Reachable from elsewhere by |
|---|---|---|
| `TFT_eSPI tft`, all rendering | `loopTask` **exclusively** | nothing — data crosses as numbers, never draw calls |
| SPIFFS, settings, playlist model, file browser | `loopTask` | nothing |
| SD / FATFS volume | `loopTask` + pump task (its own open file only) | FATFS VFS per-volume serialisation |
| The single `Audio` object | audio engine | M3, then M4 |
| Spotify TLS session (~40 KB) | `spotifyTask` | `tlsYield()` / `tlsResume()` |
| `dataTask` queue + result slots | `dataTask` | M1 |
| `vu::` level / spectrum statics | pump task (writer) | M2 |
| App error state (`hasError()`) | the app instance | shell reads only |
| `prLat`/`prLon` | write-through mirror of `prLocs[active]` | single writer path |

**Invariants**:

- **I1** — at most one TLS session may be *establishing* at a time. A context opening TLS must
  `tlsYield()` first and `tlsResume()` on **every** exit path, including early returns.
  `tlsTryYield(ms)` returning `false` means **no yield was granted — do not resume.**
- **I2** — no context but `loopTask` calls `tft.*`, directly or transitively.
- **I3** — no context but `loopTask` touches SPIFFS, settings, the playlist model or the file
  browser. The pump task may read its own open audio file and nothing else.
- **I4a — event callbacks on the pump task may only set a flag.** `audio_eof_mp3`, `audio_info`,
  `audio_showstreamtitle`. They run at priority 2 with the engine mutex held; acting inside one
  self-deadlocks. Flags are drained on `loopTask`.
- **I4b — the streaming-data callback is M2, not a flag.** `audio_process_extern`
  (`audio/audioEngine.h:209`) legitimately computes on the pump task every decoded block: a rectified
  peak scan, then a 19-band Goertzel, writing `vu::lLevelRef()`/`rLevelRef()` and the spectrum bars.
  That is the **single-writer-static** mechanism (M2), and it is correct by construction — one writer,
  no drain, no assert needed. It is **not** a violation of I4a and must not be "fixed" into one.

  > *Corrected on @VE review, 2026-08-16.* v1 stated a single I4 — "may only set a flag" — and listed
  > `audio_process_extern` among its examples. That was **false about one of its own four examples**,
  > and `T_CC_03` as first written would have failed on inspection. Two different mechanisms with
  > two different enforcement stories were sharing one invariant number.

- **I5 — results carry identity *where a stale reply could apply against changed consumer state*.**
  Where they do, a reply whose identity does not match the outstanding request is **discarded, not
  applied**; staleness is not detectable from payload content. This is IFC-001 invariant 5's
  conditional rule, not a universal. The actual set today is **three of nine**:
  `stockChart` (symbol echo), `planeRadar` (epoch), `geocode` (seq). Weather, Crypto, Stock quote,
  Heatmap and WebRadio stations carry **none** — IFC-001's own message table records this as
  *"none (single consumer)"* and *"none (abort covers the race)"*.

  > *Corrected on @VE review, 2026-08-16 — this was a **BLOCKER**.* v1 asserted "**every**
  > cross-context result carries a monotonic seq or epoch", citing IFC-001 as the house standard
  > while contradicting IFC-001's own table. A universal was written from a conditional rule.
- **I6** — a write-through mirror has exactly one writer path; consumers read only the mirror.
- **I7** — a priority-1 task must not block without feeding the TWDT; blocking starves the other two.
- **I8** — `mb_arena_acquire()` is an idempotent latch, not a refcount. Multiple releases along
  different exit paths are the intended shape.
- **I9 — `switchApp()` itself is loopTask-only.** Added on @VE review: the contract covered the nine
  `App` methods but not the shell's own entry point. `switchApp()` is declared in `appShell.h` with
  **no handle assert**, unlike `aeDrainEof()`. It touches `tft`, SPIFFS and the playlist model, so a
  future task-driven auto-switch (an alarm, a scheduled station change) calling it from any other
  context violates I2 and I3 with zero enforcement. Stated explicitly rather than left to be
  inherited.

**Error handling**:

- **Lost / late messages** — handled by I5. A late reply to a superseded request is dropped silently;
  this is normal operation, not an error.
- **Contended acquire** — `tlsYield()` blocks up to 150 s; `tlsTryYield(ms)` is the bounded variant
  for contexts that must stay responsive (a PLEDIT row tap). Timeout returns `false` with the
  requester count rolled back, so a timed-out caller can never strand `spotifyTask` stopped.
- **Deadlock** — the known shape is resume-then-yield back-to-back on the same task, and acting inside
  an I4a callback. Both are prevented by construction, not detected at runtime.
- **Violation of I2/I3/I5** — **currently undetected.** See enforcement below.

**Enforcement** — stated honestly, because the asymmetry is the point:

| Invariant | Enforcement | Strength |
|---|---|---|
| I4a | `configASSERT(xTaskGetCurrentTaskHandle() == g_loopTaskHandle)` (ADR-059 D12) | **runtime, strong** |
| I4b | correct by construction (single writer) | n/a — no test needed |
| I1 | comments + BP-031 | weak — TASK-222 is a documented failure of exactly this. **Not "guaranteed by construction after TASK-458"**: that task is OPEN and gated behind TASK-495, an unresolved judgement call (@VE, 2026-08-16). Today this is manual comment discipline, nothing more. |
| I2, I3, I5, I9 | convention | **none** |
| I7 | TWDT | post-hoc detection only |

I4a is the only invariant with an assert, and the only one that has stopped recurring. Extending the
same handle-comparison assert to I2/I3 costs a few bytes in debug builds and is the single highest-value
hardening available — tracked as M-CONCURRENCY G2.

**Known gaps**: G1 the WiFi radio has no arbiter (two fixed collisions plus one untested hypothesis,
per M-CONCURRENCY §5); G2 I2/I3/I5 unenforced (now unblocked, see M-CONCURRENCY TASK-473 row); G3
two write-through mirrors now coexist, and R7 already fails for the first one singly; G6 `promiscCb`
crosses `beaconStats` to `loopTask` by unlocked read-modify-write across two cores, no M1-M4
mechanism applies; G7 `wifiDiag::onEvent`'s counter group crosses with no lock and no identity. G6/G7
tracked as TASK-544.
