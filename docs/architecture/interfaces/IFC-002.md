### IFC-002 — task-ownership and cross-context data exchange

**Parties**: `loopTask` (Arduino) ↔ `spotifyTask` ↔ `dataTask` ↔ `wrAudio` pump task
**Transport**: shared memory on one core — `portMUX` spinlocks, FreeRTOS mutexes/queues, single-writer statics
**Protocol**: ownership-per-resource; four permitted crossing mechanisms (see Message types)
**Direction**: bidirectional, all pairs

**Worked out in**: [M-CONCURRENCY-task-ownership-contract.md](../designs/M-CONCURRENCY-task-ownership-contract.md)
— rationale, bug lineage and the cross-feature-matrix mining live there; this file is the obligation.

---

**Execution contexts** (measured, not assumed):

| Context | Core | Prio | Stack | Created at |
|---|---|---|---|---|
| `loopTask` | 1 | 1 | 20 480 B | framework |
| `spotifyTask` | 1 | 1 | 10 240 B | `spotifyTaskStorage.cpp:591` |
| `dataTask` | 1 | 1 | 11 264 B (14 336 debug) | `dataTaskStorage.cpp:1682` |
| `wrAudio` pump | 1 | **2** | 8 192 B | `audio/audioEngine.h:649` |

**All four are pinned to core 1.** There is no true parallelism between them; core 0 runs WiFi/lwIP.
Every race here is a **preemption** race, and the priority-2 pump task can preempt the other three at
any instruction. Code that is safe only because it is never preempted mid-sequence is safe **by
scheduling, not by construction** — changing a priority or a pinning invalidates it.

**Message types** — the only permitted ways data crosses a context boundary:

| Type | ID | Payload | Description |
|---|---|---|---|
| Spinlock-published result | M1 | fixed struct, copied into caller storage | `portENTER_CRITICAL_SAFE` around publish and read; used for all `dataTask` results |
| Single-writer static | M2 | scalar | exactly one writing context, any number of readers; no lock (`vu::lLevelRef()`) |
| Mutex-guarded singleton | M3 | the resource itself | one hardware object behind one mutex (`s_wrAudioMutex` → `Audio`) |
| Post-request / poll-result | M4 | request struct + result enum | for anything that would block the caller (`wrPumpConnect`) |

Anything not M1–M4 is a contract violation, including "it's just a bool".

**Ownership**:

| Resource | Owner | Reachable from elsewhere by |
|---|---|---|
| `TFT_eSPI tft`, all rendering | `loopTask` **exclusively** | nothing — data crosses as numbers, never draw calls |
| SPIFFS, settings, playlist model, file browser | `loopTask` | nothing |
| SD / FATFS volume | `loopTask` + pump task (its own open file only) | FATFS VFS per-volume serialisation |
| The single `Audio` object | audio engine | M3, then M4 |
| Spotify TLS session (~40 KB) | `spotifyTask` | `tlsYield()` / `tlsResume()` |
| `dataTask` queue + result slots | `dataTask` | M1 |
| `vu::` level / spectrum statics | pump task (writer) | M2 |
| App error state (`hasError()`) | the app instance | shell reads only |
| `prLat`/`prLon` | write-through mirror of `prLocs[active]` | single writer path |

**Invariants**:

- **I1** — at most one TLS session may be *establishing* at a time. A context opening TLS must
  `tlsYield()` first and `tlsResume()` on **every** exit path, including early returns.
  `tlsTryYield(ms)` returning `false` means **no yield was granted — do not resume.**
- **I2** — no context but `loopTask` calls `tft.*`, directly or transitively.
- **I3** — no context but `loopTask` touches SPIFFS, settings, the playlist model or the file
  browser. The pump task may read its own open audio file and nothing else.
- **I4** — a callback invoked on the pump task (`audio_eof_mp3`, `audio_info`,
  `audio_showstreamtitle`, `audio_process_extern`) **may only set a flag.** It runs at priority 2 with
  the engine mutex held; acting inside it self-deadlocks. Flags are drained on `loopTask`.
- **I5** — every cross-context result carries a monotonic `seq` or `epoch` echoed from its request.
  A reply whose identity does not match the outstanding request is **discarded, not applied**.
  Staleness is not detectable from payload content.
- **I6** — a write-through mirror has exactly one writer path; consumers read only the mirror.
- **I7** — a priority-1 task must not block without feeding the TWDT; blocking starves the other two.
- **I8** — `mb_arena_acquire()` is an idempotent latch, not a refcount. Multiple releases along
  different exit paths are the intended shape.

**Error handling**:

- **Lost / late messages** — handled by I5. A late reply to a superseded request is dropped silently;
  this is normal operation, not an error.
- **Contended acquire** — `tlsYield()` blocks up to 150 s; `tlsTryYield(ms)` is the bounded variant
  for contexts that must stay responsive (a PLEDIT row tap). Timeout returns `false` with the
  requester count rolled back, so a timed-out caller can never strand `spotifyTask` stopped.
- **Deadlock** — the known shape is resume-then-yield back-to-back on the same task, and acting inside
  an I4 callback. Both are prevented by construction, not detected at runtime.
- **Violation of I2/I3/I5** — **currently undetected.** See enforcement below.

**Enforcement** — stated honestly, because the asymmetry is the point:

| Invariant | Enforcement | Strength |
|---|---|---|
| I4 | `configASSERT(xTaskGetCurrentTaskHandle() == g_loopTaskHandle)` (ADR-059 D12) | **runtime, strong** |
| I1 | comments + BP-031 | weak — TASK-222 is a documented failure of exactly this |
| I2, I3, I5 | convention | **none** |
| I7 | TWDT | post-hoc detection only |

I4 is the only invariant with an assert, and the only one that has stopped recurring. Extending the
same handle-comparison assert to I2/I3 costs a few bytes in debug builds and is the single highest-value
hardening available — tracked as M-CONCURRENCY G2.

**Known gaps**: G1 the WiFi radio has no arbiter (three bugs: X014, TASK-436, TASK-404); G2 I2/I3/I5
unenforced; G3 two write-through mirrors now coexist, untested as a pair.
