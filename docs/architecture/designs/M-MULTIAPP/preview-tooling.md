# M-MULTIAPP — Preview Tooling Extension

> Part of: [overview.md](overview.md)

## Goal

Resolve taskbar aesthetics (background, icon style, active indicator, separators)
before any firmware code is written. The existing `bake_skin.py` preview
infrastructure is extended to render a full 320×240 layout mockup that includes
the taskbar strip.

This is the **gate** for taskbar.md's open questions. Implementation of
`renderTaskbar()` and icon glyph arrays is blocked until this pass produces
an approved composite.

## New output: `gen/layout_preview.png`

A full 320×240 composite showing the final on-device pixel layout:

```
[275×116 Winamp main window, originX=0] | [45×116 taskbar top]
[275×124 PLEDIT / app canvas]           | [45×124 taskbar bottom]
```

Generated by a new function `render_layout_preview()` in `bake_skin.py`
(or a thin wrapper script `preview_layout.py` that imports bake_skin).

### Rendering steps

1. **Base canvas** — 320×240 black PIL Image.
2. **Winamp main window** — paste existing `SKIN_MAIN_BG` composite at (0, 0).
3. **PLEDIT region** — paste `SKIN_PLEDIT_BG` at (0, 116).
4. **Taskbar background** — fill rect (275, 0, 45, 240) with candidate colour
   (parameterise: `--taskbar-bg #232323`).
5. **Separator lines** — draw horizontal rules at y = 40, 80, 120, 160, 200
   within x: 275..319 (parameterise: `--sep-color #444444` or `none`).
6. **Icon glyphs** — render placeholder glyphs (letters S/C/W/€/M/G in a small
   font, or hand-drawn 24×24 bitmaps if available) centred in each 45×40 cell.
7. **Active indicator** — draw the candidate indicator style for slot 0 (Spotify):
   - Style A: 3 px left-edge bar (x=275..277, y=0..39), colour parameterised.
   - Style B: full cell background fill (contrast colour).
   - Style C: small dot at cell centre-left.
   Parameterise: `--active-style A|B|C --active-color #00ff00`.
8. **Hit-zone overlay** (optional, `--hitzones`) — semi-transparent magenta
   rects over each taskbar cell, labelled with app name, in the same style as
   the existing `render_hitzones()`.

### CLI

```sh
cd Spotify-Diy-Thing/tools
python3 bake_skin.py -i ../skins/base-2.91.wsz -o ../SpotifyDiyThing/gen \
    --layout-preview \
    --taskbar-bg "#232323" \
    --sep-color "#444444" \
    --active-style A \
    --active-color "#1db954"
# output: gen/layout_preview.png
```

Run multiple times with different `--active-style` and colour values to compare.
The approved parameters are then hardcoded into the firmware's `renderTaskbar()`.

## Icon glyph strategy (options)

Three options for the 24×24 icon glyphs; resolved during the preview pass:

**Option A — TFT_eSPI GLCD font characters.**
Single ASCII chars (S, C, W, $, M, G) rendered via `tft.drawChar()` at
appropriate size. Zero flash cost for glyphs; not pixel-perfect icons.
Prototype: bake_skin.py renders PIL's built-in bitmap font into the preview.

**Option B — Hand-drawn 24×24 RGB565 arrays.**
Draw icons in Aseprite or GIMP at 24×24, export as C arrays via a small
`img2c.py` helper. Flash cost: 6 × 24 × 24 × 2 B = 6912 B ≈ 6.75 KB.
Prototype: placeholder PNGs drawn by bake_skin.py using PIL shape primitives.

**Option C — Skin-extracted glyphs.**
Winamp 2 skin bundles unused bitmap regions (EQ sliders, scrollbar parts)
that could be repurposed as icons. Requires identifying suitable 24×24
sub-regions in the WSZ. Not guaranteed to yield usable art.

Start with **Option A** in the preview (fastest to iterate); switch to B if
the result is too crude.

## Excluded from golden.sha256

`gen/layout_preview.png` is excluded from the determinism check
(`golden.sha256`) in the same way as `gen/skin_hitzones.png` — it is a
developer preview artifact, not a firmware input.

## Exit criteria for this tooling pass

- `bake_skin.py --layout-preview` generates `gen/layout_preview.png` without
  error on the standard `python3 bake_skin.py -i ../skins/base-2.91.wsz` run.
- At least three taskbar style variants have been rendered and compared.
- Taskbar background colour, active indicator style, separator style, and icon
  approach are documented in taskbar.md (open questions section updated).
- `golden.sha256` excludes `layout_preview.png` (verify `sha256sum -c` still
  passes after the new output is added).
