# M-APP-REGISTRY — Single-source app registry

> Architect design doc · 2026-06-06  
> ADR: [ADR-041](../decisions/ADR-041.md)  
> Status: **proposed**

---

## Problem

App order and identity are encoded in six separate files. To add, remove,
reorder, or disable one app the developer must make consistent edits in all of:
`appShell.h`, `taskbar.h`, `main.cpp`, `settings/appsSection.h`,
`run_serialdbg_tests.py`, and `test_tls_yield_reliability.py`. Any drift is a
silent runtime bug (wrong icon, wrong settings list, wrong test slot number).

There is also no mechanism to disable an app at build time.

---

## Solution: X-macro table

### 1. New file: `app/src/appRegistry.h`

One row per app. Comment a row out to disable that app — the entire build and
test suite adapt automatically.

```c
// appRegistry.h — canonical app list. Each row: X(Name, icon, configurable)
// Comment out a row to disable the app at build time.
//
//  Name       icon  configurable (1 = appears in Settings > Applications)
APP_X(Spotify,  'S',  0)
APP_X(Clock,    'C',  0)
APP_X(Weather,  'W',  0)
APP_X(Crypto,   '$',  1)
APP_X(Matrix,   'M',  1)
APP_X(Life,     'G',  1)
APP_X(Settings, '=',  0)
APP_X(Stock,    'K',  1)
APP_X(Aquarium, '~',  1)
```

The file is **pure data** — no `#include`, no guards, no `#define APP_X`.
Callers define `APP_X(name, icon, cfg)` before including, then `#undef APP_X`
after.

### 2. Changes to existing C++ files

#### `appShell.h` — AppId enum

Replace the hand-written enum with an X-macro expansion:

```c
#define APP_X(Name, icon, cfg) Name,
enum class AppId : uint8_t {
#include "appRegistry.h"
    COUNT,
};
#undef APP_X
```

`g_appLaunched` sizing (`AppId::COUNT`) and all `(int)AppId::COUNT` call-sites
in `main.cpp` continue to work unchanged — `COUNT` is still the sentinel.

#### `taskbar.h` — icons[] array

```c
inline void renderTaskbar(...) {
    #define APP_X(Name, icon, cfg) icon,
    const char icons[] = {
    #include "appRegistry.h"
    };
    #undef APP_X
    ...
}
```

#### `main.cpp` — g_apps[] dispatch table

All nine app objects are defined `static` in `main.cpp` and are already
visible at the `g_apps[]` initialiser site — **no forward-declaration block is
needed or correct** (mixing `extern` and `static` on the same name in the same
TU is ill-formed in C++). Only the dispatch-table initialiser uses the macro:

```c
// Dispatch table (indexed by AppId)
App* g_apps[(int)AppId::COUNT] = {
#define APP_X(Name, icon, cfg) &g_##Name##App,
#include "appRegistry.h"
#undef APP_X
};
```

App object names follow `g_<Name>App` — **capitalised** first letter of
`Name`. Current globals use lowercase (`g_spotifyApp` etc.); rename them with
a scoped word-boundary sed pass on `main.cpp` only:

```sh
for pair in "Spotify:spotify" "Clock:clock" "Weather:weather" "Crypto:crypto" \
            "Matrix:matrix" "Life:life" "Settings:settings" "Stock:stock" \
            "Aquarium:aquarium"; do
  upper="${pair%%:*}"; lower="${pair##*:}"
  sed -i "s/\\bg_${lower}App\\b/g_${upper}App/g" app/src/main.cpp
done
```

Run `check_build.sh` immediately after the sed pass to catch any missed
reference at link time.

#### `settings/appsSection.h` — configurable app list

Filter the macro on `cfg == 1`:

```c
// Count configurable apps
#define APP_X(Name, icon, cfg) + cfg
static constexpr int kConfigurableCount = 0
#include "appRegistry.h"
;
#undef APP_X

// Name table (only configurable entries)
#define APP_X(Name, icon, cfg) , cfg ? #Name : nullptr
static const char* kNames_raw[] = { nullptr
#include "appRegistry.h"
};
#undef APP_X
```

The nullptr-filtering trick is awkward. Cleaner approach: generate a
**separate** header `app/gen/configurable_apps.h` via the codegen script
(see §3 below) with an explicit list of configurable app names and their
`AppId` values. `appsSection.h` includes this generated header instead of
re-expanding the macro itself.

This also makes the settings section simpler — the switch dispatch on `_sub`
becomes a loop over the generated table.

### 3. New file: `app/tools/gen_app_registry.py`

Parses `appRegistry.h` and writes two outputs:

**`app/tools/app_ids_gen.py`** — Python-side mirror for tests:
```python
# AUTO-GENERATED by gen_app_registry.py — do not edit by hand.
# Re-run: python3 app/tools/gen_app_registry.py
APP_ORDER = ["Spotify","Clock","Weather","Crypto","Matrix","Life","Settings","Stock","Aquarium"]
APP_SLOT  = {name: i for i, name in enumerate(APP_ORDER)}
CONFIGURABLE = {"Crypto","Matrix","Life","Stock","Aquarium"}
APP_COUNT = len(APP_ORDER)
```

**`app/gen/configurable_apps.h`** — C header for `appsSection.h`:
```c
// AUTO-GENERATED — do not edit. Re-run gen_app_registry.py.
#define CONFIGURABLE_APP_COUNT 5
static const struct { const char* name; AppId id; } kConfigurableApps[] = {
    { "Crypto",   AppId::Crypto   },
    { "Matrix",   AppId::Matrix   },
    { "Life",     AppId::Life     },
    { "Stock",    AppId::Stock    },
    { "Aquarium", AppId::Aquarium },
};
```

The script is simple (~50 lines): regex-parse `APP_X(...)` lines, skip
commented-out rows, emit both files. Checked in. Run on demand.

**Staleness gate (required)**: `check_build.sh` gains a new step [5/5] that
re-runs `gen_app_registry.py` into a temp dir and diffs against checked-in
files. Any mismatch fails the build check — this is the only mechanical guard
that makes the "single source of truth" claim true end-to-end.

### 4. Changes to test suite

#### `run_serialdbg_tests.py` and `test_tls_yield_reliability.py`

Import from generated file instead of hardcoding:

```python
from app_ids_gen import APP_SLOT, CONFIGURABLE, APP_COUNT

# Was: _STOCK_APP_ID = 7
# Now: implicitly APP_SLOT["Stock"]

# Was: _switch_to(dut, "Matrix", 4)
# Now: _switch_to(dut, "Matrix", APP_SLOT["Matrix"])
```

`_STOCK_APP_ID`, `_SPOTIFY_APP_ID`, etc. become one-line aliases or disappear
entirely:

```python
# Thin aliases for readability (optional)
_STOCK_APP_ID    = APP_SLOT["Stock"]
_SPOTIFY_APP_ID  = APP_SLOT["Spotify"]
_CLOCK_APP_ID    = APP_SLOT["Clock"]
_CRYPTO_APP_ID   = APP_SLOT["Crypto"]
_WEATHER_APP_ID  = APP_SLOT["Weather"]
_SETTINGS_APP_ID = APP_SLOT["Settings"]
```

#### `_switch_to` robustness for disabled apps

Add a guard at the top of test functions that navigate to an app:

```python
if "Matrix" not in APP_SLOT:
    skip("T_MATRIX_01", "Matrix app disabled in registry")
    return
```

Or add a helper:
```python
def _require_app(name: str, tid: str) -> bool:
    if name not in APP_SLOT:
        skip(tid, f"{name} app disabled in registry")
        return False
    return True
```

#### `coords.py` — `tap_taskbar_slot`

No change needed; it takes a slot index and computes coordinates. With the
migration from hardcoded ints to `APP_SLOT["Matrix"]` the semantics are
identical.

#### `_TB_N` constant (line 3768)

```python
# Was: _TB_N = 8  # AppId::COUNT - 1
from app_ids_gen import APP_COUNT
_TB_N = APP_COUNT - 1
```

## What stays the same

- `switchApp(AppId::X)` call sites in `main.cpp` — the enum names are stable.
- `AppId::COUNT` sentinel — still the last enum value.
- The taskbar gesture / scroll logic — unchanged.
- `(int)AppId::COUNT` used as `totalApps` in taskbar rendering — unchanged.
- `g_previousAppId` / Settings back-navigation — unchanged.
- Serial command `switchApp <N>` for manual debugging still works (numeric
  IDs may shift if apps are disabled, but that's acceptable for a dev tool).
  Optionally add `switchApp <name>` variant for robustness.

---

## Disable-app workflow (steady state)

1. Comment out one `APP_X(...)` row in `appRegistry.h`.
2. `python3 app/tools/gen_app_registry.py`
   — regenerates `app_ids_gen.py` and `configurable_apps.h`.
3. `./check_build.sh` — confirm firmware still compiles; update golden hash.
4. `pio run -e cyd2usb_winamp -t upload` — flash.
5. Test suite automatically skips tests for disabled apps.

## File change summary

| File | Change |
|------|--------|
| `app/src/appRegistry.h` | **new** — X-macro table (the golden source) |
| `app/src/appShell.h` | AppId enum → X-macro expansion |
| `app/src/taskbar/taskbar.h` | `icons[]` → X-macro expansion |
| `app/src/main.cpp` | `g_apps[]` → X-macro; rename `g_spotifyApp` → `g_SpotifyApp` etc. |
| `app/src/settings/appsSection.h` | Replace hardcoded 5-app list with `kConfigurableApps[]` from generated header |
| `app/tools/gen_app_registry.py` | **new** — codegen script |
| `app/tools/app_ids_gen.py` | **new (generated)** — Python-side mirror |
| `app/gen/configurable_apps.h` | **new (generated)** — C configurable-app table |
| `app/tools/run_serialdbg_tests.py` | Replace `_*_APP_ID` constants and `_switch_to(…, slot)` literals with `APP_SLOT` lookups |
| `app/tools/test_tls_yield_reliability.py` | Same as above |
| `app/gen/golden.sha256` | Update after firmware rebuild |

## Verification

1. `./check_build.sh` passes (both `cyd2usb_winamp` and `cyd2usb_winamp_debug`).
2. Flash firmware; verify all 9 apps appear in taskbar and are reachable.
3. Comment out `APP_X(Aquarium, ...)`, re-run codegen, rebuild, flash — Aquarium
   disappears from taskbar and Settings > Applications. Restore + rebuild.
4. Run `python3 app/tools/run_serialdbg_tests.py` against
   DUT — all previously-passing tests still pass.
5. Reorder two apps in `appRegistry.h`, re-run codegen, rebuild — taskbar
   shows new order; tests navigate correctly via `APP_SLOT` lookups.
