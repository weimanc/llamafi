# ADR-036 — StockApp Heatmap View

> Status: accepted
> Date: 2026-05-31
> Updated: 2026-06-02 — JSON budget corrected from live measurement; all open questions closed

---

## Context

StockApp (stock-001) has two sub-views: `ListDetail` (8 hardcoded tickers) and `ChartDetail` (line chart for a single ticker). The user wants a third sub-view — a squarified treemap heatmap of the global tech sector top-25, toggling with the list view, with drill-through to chart.

Key constraints:
- ESP32 heap: HTTP fetches must use `getStream()` + ArduinoJson filter (ADR-034)
- Canvas: 275×240 full-screen (full-canvas rule)
- Existing list view tests (T169–T188) must not be disturbed

---

## Decisions

### D1 — Sub-view model

Add `HeatmapDetail` to the `StockSubView` enum alongside `ListDetail` and `ChartDetail`.

Navigation model:
```
ListDetail  ←[toggle]→  HeatmapDetail
     ↓                        ↓
  ChartDetail             ChartDetail
        ↑                     ↑
        └────── back ──────────┘  (returns to launching view)
```

`StockAppState` gains a `prevSubView` field. On `drillToChart()`, save current sub-view to `prevSubView`. Back tap from `ChartDetail` restores `prevSubView` (not always `ListDetail`).

Toggle button lives in the header strip of both `ListDetail` and `HeatmapDetail`:
- **Tap zone:** `x > 190 && y < ST_LIST_RULE_Y (22)` — right side of header, consistent with chart tab placement at `ST_CHART_TABS_X = 130`. Gives ~84 px width, clear of "STOCK TERMINAL" / "HEATMAP" title text at x = 5.
- **Render:** `[Heat]` label in `ListDetail` header; `[List]` label in `HeatmapDetail` header. Same font-2 style as chart tab labels.
- **ListDetail header y-bound:** `ST_LIST_RULE_Y = 22` (matches existing rule line, not chart's `ST_CHART_HEADER_H = 18`).

### D2 — Data source

Yahoo Finance screener endpoint, one request:

```
GET https://query1.finance.yahoo.com/v1/finance/screener/predefined/saved
    ?scrIds=ms_technology&count=20&formatted=false
```

- Same host as existing chart fetch (`query1.finance.yahoo.com`) — same root CA, no change to TLS setup
- No auth required
- Returns top-20 global tech stocks by market cap (includes TSM, ASML, ARM, SAP)
- Ticker list is Yahoo-maintained and market-cap sorted; treated as fully dynamic
- Fields used: `symbol`, `regularMarketPrice`, `regularMarketChangePercent`, `marketCap`

### D3 — Separate fetch pipeline, lazy trigger

New dataTask op: `DATA_FETCH_HEATMAP_QUOTE`.

- **Lazy:** only enqueued when `HeatmapDetail` is entered (or refresh interval elapsed while in view)
- **Independent** of `DATA_FETCH_STOCK_QUOTE` (list pipeline); no coupling
- **Refresh interval:** 120s while `HeatmapDetail` is active
- `lastHeatmapFetch` timestamp in `StockAppState`; 0 = never fetched

List quote pipeline (`DATA_FETCH_STOCK_QUOTE`, 8 hardcoded tickers, 60s) is **unchanged**.

### D4 — HeatmapQuoteResult struct

```cpp
struct HeatmapQuoteResult {
    bool    ok            = false;
    int     errorCode     = 0;
    uint8_t count         = 0;        // valid entries (up to 20)
    char    symbols[20][8] = {};      // ticker symbols from response
    float   prices[20]    = {};       // regularMarketPrice
    float   changePct[20] = {};       // regularMarketChangePercent
    float   marketCap[20] = {};       // marketCap (relative use only)
};
```

ArduinoJson filter + streaming parse per ADR-034. Two separately-sized documents:

```cpp
// Filter doc: 5-level path × 4 leaves → ~140B ArduinoJson minimum; <256> gives headroom.
// HOST TEST: test_yahoo_finance_api.py T_SF_HM_* HEATMAP_FILTER_DEPTH / HEATMAP_LEAF_COUNT
StaticJsonDocument<256> filter;
auto q = filter["finance"]["result"][0]["quotes"][0];
q["symbol"]                     = true;
q["marketCap"]                  = true;
q["regularMarketPrice"]         = true;
q["regularMarketChangePercent"] = true;

// Data doc: measured 2026-06-02 — raw payload 54,826 B; filtered JSON (4 fields × 20 quotes)
// = 2,330 B; ArduinoJson capacity (Broder formula: 2330 × 1.5 + 128) ≈ 3,623 B minimum.
// <4096> gives ~473 B headroom. Prior estimate of <2048> was under-sized by ~1,575 B.
// HOST TEST: test_yahoo_finance_api.py T_SF_HM_* HEATMAP_DOC_CAPACITY
StaticJsonDocument<4096> doc;
deserializeJson(doc, http.getStream(), DeserializationOption::Filter(filter));
```

### D5 — Runtime squarified treemap

Tile layout is computed on-device each time a new `HeatmapQuoteResult` arrives.

```cpp
struct HeatmapTile {
    uint16_t x, y, w, h;
    uint8_t  tickerIdx;   // index into HeatmapQuoteResult.symbols[]
};
```

`StockAppState` holds `HeatmapTile heatmapLayout[20]` and a `heatmapLayoutDirty` flag. When `tick()` detects new heatmap data, it calls `computeHeatmapLayout()` which runs the Bruls et al. squarified treemap algorithm on the 20 market-cap values. Canvas: 275×240. No heap allocation — sort on a local index array, write output to `heatmapLayout[]` in place.

**Strip direction: landscape-first.** Initial strip is horizontal, filling the full canvas width (275 px). 275/240 = 1.15 aspect ratio — wider than tall — so landscape-first produces more square tiles on the first strip than portrait-first would. Each subsequent strip adds rows below.

### D6 — Tile label rendering (adaptive)

Each tile renders:
- **Always:** ticker symbol (e.g. `NVDA`)
- **If tile width ≥ 40px AND height ≥ 28px:** also render change% on second line (e.g. `+3.2%`). Font-2 char height is ~16 px; two lines at minimum spacing fit within 28 px. Verify on first DUT flash — trivial to adjust if clipping observed.

Tile background color encodes change%:
- Green family: positive change (intensity proportional to magnitude, cap at ±5%)
- Red family: negative change
- Neutral (dark grey): change% == 0 or data not yet received

### D7 — Chart drill-in from heatmap

New function:
```cpp
static void fetchStockChartBySymbol(const char* symbol, uint8_t rangeIdx);
```

Mirrors `fetchStockChart()` but takes a symbol string instead of a static ticker index. Heatmap tile tap passes `heatmapData.symbols[tile.tickerIdx]` directly.

Existing `fetchStockChart(uint8_t tickerIdx, uint8_t rangeIdx)` is **unchanged** — used by list drill-in only.

### D8 — Error handling

If `DATA_FETCH_HEATMAP_QUOTE` fails (network error, screener endpoint down, JSON parse error):
- `HeatmapQuoteResult.ok = false`, `errorCode` set
- `HeatmapDetail` renders the existing error state (consistent with list error path)
- No static fallback ticker list
- Retry on next 120s interval

### D9 — List view unchanged

`STOCK_TICKERS[8]` (`AAPL AMD AMZN ARM GOOG META MSFT NVDA`), `StockQuoteResult`, and all list rendering code are **unchanged**. Tests T169–T188 are unaffected.

## Consequences

**Easier:**
- Heatmap ticker list stays current automatically (Yahoo-maintained)
- Global tech sector coverage (TSM, ASML, ARM, SAP included)
- Single screener request for all 25 tickers + market caps (~2s vs ~37s for 25 individual calls)
- List view tests require no revision

**Harder:**
- Chart drill-in from heatmap requires new `fetchStockChartBySymbol` path
- Squarified treemap algorithm must be implemented on-device (~60-80 lines C++)
- `prevSubView` back-nav adds state to test harness (T-HEAT-* tests must verify back target)
- Screener endpoint `ms_technology` is undocumented Yahoo API — could change without notice; error state is the only mitigation

**Constrained:**
- Heatmap tile count fixed at 20 (screener `count=20`); layout algorithm must handle 1..20 valid entries
- `StaticJsonDocument<4096>` data doc has ~473 B margin over the measured minimum (2026-06-02 live payload); upsize to `<6144>` only if screener response grows materially (new fields added by Yahoo)
