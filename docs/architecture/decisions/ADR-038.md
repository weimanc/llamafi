# ADR-038 — CPU Optimisation: LUT, Fast rsqrt, Reciprocal Constants (Aquarium + VuMeter)

> Status: accepted (2026-06-04 — all 16 VE criteria pass; human visual sign-off received)
> Date: 2026-06-04
> Amended: 2026-06-04 — extended scope to vuMeter.h and shared mathUtil.h
> Design: docs/architecture/designs/M-AQUARIUM/cpu-opt.md

---

## Context

A codebase-wide scan identified two components with significant per-frame trig cost:

**AquariumApp** (`aquariumApp.h`): ~196 `sinf`/`cosf` and ~80–320 `sqrtf` per frame.
Trig consumes ~65 µs/frame; sqrt ~50 µs typical. `updateClock()` also calls `time()` +
`localtime_r()` (POSIX syscalls) 30×/second when the display only changes at 1 Hz.

**VuMeter** (`vuMeter.h`): `tickWave` calls `sinf` 76 times per frame inside a pixel
loop — the single largest trig hotspot in the codebase outside aquarium. `tickSpectrum`
has 2 per-iteration float divisions in a 19-bar loop.

Demoscene-opt already freed ~21 KB of DRAM from `AquariumApp`. This ADR addresses CPU.

---

## Decision

Adopt the four-phase CPU optimisation plan from `cpu-opt.md`:

**Phase 1 — Trivial (P1):**
- Throttle `updateClock()` to 1 Hz (add `_lastClockUpdateMs` member, early-return if
  `millis() - _lastClockUpdateMs < 1000`).
- Replace `/ 9999.0f` in `_frand` with `* kInv9999` (`constexpr float`).
- Replace four `/ nearCount` divides in `updateFish` with `float invN = 1.0f/nearCount`
  + four multiplies.

**Phase 2 — Reciprocal constants (P2):**
- Add 12 `constexpr float` reciprocals for all radius denominators that appear in the
  fish-loop inner body (`kInvFishAvoidRX/RY`, `kInvOctFishAv/ClRX/RY`,
  `kInvSHFishAv/ClRX/RY`, `kInvVisClRX/RY`).
- Replace every `dx/RADIUS_X` division at the 6 affected sites with `dx * kInvRadiusX`.

**Phase 3 — Shared math utility + fast rsqrt (P3):**
- Create `app/src/util/mathUtil.h` + `mathUtil.cpp` containing `q_rsqrt`, `lut_sin`,
  `lut_cos`, `buildMathLUT()`, and `extern float g_sinLUT[512]`.
- Call `buildMathLUT()` once in `main.cpp:setup()`.
- In `aquariumApp.h`: replace `1.0f / sqrtf(sd2)` at `:610`, `:630`, `:834`;
  fold `sqrtf`+`/dist` in `_steerFromOctopus:576` and `_steerFromSeahorse:590`;
  replace velocity normalisation at `:723-725`.

**Phase 4 — VuMeter wave rotation matrix (P4):**
- In `vuMeter.h:tickWave`: replace the 76-iteration `sinf` loop with the rotation
  matrix pattern. Seed `wave=sinf(wavePhase)`, `waveC=cosf(wavePhase)` once per
  frame; advance per pixel with `static const float kWaveSin/kWaveCos` (computed
  once from `kWaveStep = WAVE_CYCLES * TWO_PI_F / RECT_W`).
- In `vuMeter.h:tickSpectrum`: replace `ei / 18.0f`, `specH[i] / VIS_H`,
  `1.0f / VIS_H` with `constexpr` reciprocals `kInv18`, `kInvVisH`.
- In `vuMeter.h:tick()`: replace three LFO `sinf` calls with `lut_sin` + inline
  `* reciprocal` for the time-scaling divisions.
- In `main.cpp`: replace two `/ 1000.0f` with `* 0.001f`.

**Phase 5 — Trig LUT across all sites (P5):**
- In `aquariumApp.h`: replace all 41 `sinf`/`cosf` call sites with `lut_sin`/`lut_cos`.
  Remove the old per-class `_buildSinLUT` / `s_sinLUT` member (now in `mathUtil.h`).
- No changes to `vuMeter.h` beyond P4 (LFO calls already converted there).

**Instrumentation (all phases):**
- Add four `uint32_t` perf accumulators (`_perfCycUpdate`, `_perfCycDraw`,
  `_perfCycTick`, `_perfFrames`) to `AquariumApp`; emit `[aq perf]` via Serial every
  300 frames using `xthal_get_ccount()`.
- Remove or gate behind `#ifdef AQ_PERF` after final VE sign-off.

---

## Consequences

**Better:**
- Estimated ~40% reduction in combined aquarium + vuMeter tick CPU time
  (~300 µs → ~120 µs per frame).
- `tickWave` 76 sinf calls reduced to 2 — single largest saving (~50 µs/frame).
- `updateClock` syscall frequency reduced 30× (30 Hz → 1 Hz).
- All radius-division hot paths become multiplies (~16 µs/frame saved).
- `1/sqrtf` pattern eliminated from all 6 aquarium push/steer sites (~33 µs/frame).
- 44 total sinf/cosf calls/frame eliminated by LUT across both components.
- LUT is a single shared 2 KB allocation in `mathUtil.cpp` — no duplication.

**Same:**
- Fish animation, seaweed sway, bubble sway, crab leg wave, wave visualiser are
  visually unchanged. LUT error ±0.006 and rotation matrix are both sub-pixel.
- No interface changes; no new FreeRTOS tasks; no heap allocations beyond the
  2 KB static `g_sinLUT`.
- `check_build.sh` must pass after each phase.

**Worse / risks:**
- `g_sinLUT[512]` adds 2,048 B DRAM. Net cost after demoscene-opt's ~21 KB recovery:
  DRAM budget still ~19 KB better than pre-demoscene baseline.
- `q_rsqrt` has ~3% error on force magnitudes. VE must confirm fish do not visually
  penetrate visitor bounding ellipses on DUT. If they do, add a second NR step.
- P5 touches 41 call sites in `aquariumApp.h` — highest review surface. Implement
  in its own session.
- `mathUtil.h` is a new shared dependency. Any future component that includes it
  relies on `buildMathLUT()` having been called in `setup()` first — this must be
  documented in the header.
