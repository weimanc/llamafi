### ADR-033 — 2026-05-28 — AquariumApp gradient cache: static member array → heap pointer

**Status**: superseded (2026-07-16) — M-AQUARIUM-DEMOSCENE Change 1 shipped: the
gradient renders from a 32-px x-tile (`_gradTile[y][x & 31]`,
`aquariumApp.h:_buildGradTile`), which shrinks the cache to the point where a static
member is fine and heap migration is unnecessary — exactly the supersede condition
this ADR pre-declared when filed. (Flip performed by the 2026-07-16 Architect
proposed-ADR triage; the flip was pre-authorised by the status text above, so no
human sign-off gate applies.)

**Context**:

`AquariumApp` declares `uint16_t _gradientBandCache[AQ_CANVAS_W * AQ_BACKGROUND_GRADIENT_H]`
as a private member array. This places 19,800 bytes (275 × 36 × 2) in `.bss` permanently —
the array is resident for the full firmware lifetime, including all periods when the aquarium
app is suspended and another app is active.

RAM audit (2026-05-28) identified this as the single largest individually-recoverable `.bss`
allocation in the firmware. The total static DRAM footprint is 99.2 KB; the gradient cache
accounts for 19.3 KB of that, or ~19.5%.

`overview.md` Open Question #2 anticipated this: "if heap pressure causes linker complaints,
move to `heap_caps_malloc`." The audit provides the quantitative basis to act proactively
rather than waiting for a linker error.

Three options:

**Option A — Keep as member array (current).**
Simplest; no lifecycle changes. 19.3 KB permanently in `.bss`. When the app is suspended the
memory is wasted; it cannot be used by mbedTLS or the sprite allocator on other apps.
Rejected: the waste is recoverable at low cost.

**Option B — Heap pointer; allocate on `init()`/`resume()`, free on `suspend()`.**
`uint16_t* _gradientBandCache = nullptr`. Allocation follows sprite lifecycle; deallocation
precedes `deleteSprite()`. When suspended, both the sprite and the cache are absent from the
heap. When active, total heap consumption is identical to Option A.
Ruling in: recovers 19.3 KB from `.bss` on suspend; lifecycle is simple and matches the
existing sprite pattern.

**Option C — Lazy-allocate on first `drawBackground()` call; never free.**
Allocates once at first render; persists across suspend/resume. Simpler than B (no free
path) but wastes heap after first activation even when the user is on another app.
Rejected: provides no heap recovery benefit after first use.

**Decision**: **Option B.**

`_gradientBandCache` becomes a `uint16_t*` pointer, initialized `nullptr`. `init()` and
`resume()` allocate it immediately after `_calcDynamicSize()` and before
`_canvas.createSprite(...)`. `suspend()` frees it after `_canvas.deleteSprite()`.

The sprite is allocated **before** the cache — it is the larger block and must claim the
contiguous region that `_calcDynamicSize()` sized for it. The cache (19.8 KB) is allocated
second, from fragmented space left behind. `_calcDynamicSize()`'s `kMargin` must be updated
from `8192` → `27992` (`19800 + 8192`) so the sprite height is computed with the cache budget
reserved. Full allocation and retry ordering is specified in the design doc.

If the cache allocation fails (returns `nullptr`), `drawBackground()` falls back to
`_canvas.fillSprite(AQ_BG_COLOR)` — solid black background, no dithered gradient. This
graceful-degrade path already exists in the current code via the `_gradientBandCached` flag.

**Consequences**:

What becomes easier:
- 19.3 KB returns to the free heap on every app suspend. mbedTLS single-handshake peaks (~40 KB)
  fit more comfortably alongside other allocations when the aquarium is not the active app.
- Static `.bss` drops by ~19.3 KB (from 73.1 KB to ~53.8 KB), improving the ratio of heap to
  static allocation.

What becomes harder / constrained:
- `init()` and `resume()` now have a potential allocation failure path for the cache in addition
  to the existing sprite failure path. The failure is handled by existing fallback logic —
  no new error states introduced.
- `suspend()` must free the pointer correctly. A missing `delete[]` would be a heap leak;
  covered by the VE acceptance criteria (map diff confirming `.bss` reduction, not a runtime
  check).

**Supersedes**: nothing. Amends M-AQUARIUM (ADR-031) §5 "gradientBandCache as member array"
and closes `overview.md` Open Question #2.

**Implementation**: `app/src/aquarium/aquariumApp.h` only. No other files affected.
Full implementation spec: [`docs/architecture/designs/M-AQUARIUM/memory-opt.md`](../designs/M-AQUARIUM/memory-opt.md).
