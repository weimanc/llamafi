### ADR-034 — 2026-05-29 — dataTask HTTP response parsing shall use streaming, not buffered String accumulation

**Status**: accepted

**Context**:
All four fetch functions in `dataTaskStorage.cpp` (weather, crypto, stock quote, stock chart) follow the same pattern:

```cpp
DeserializationError err = deserializeJson(doc, http.getString());
```

`http.getString()` reads the full HTTP response body into a heap-allocated `String` before passing it to ArduinoJson. This means peak heap pressure at parse time is:

- raw response body (`String`) +
- `DynamicJsonDocument(N)` arena

Both allocations must succeed concurrently on the same heap. On a fragmented heap — which is normal after WiFi + TLS + multiple prior fetches — a `String` allocation for a >4 KB response can fail or return a truncated result. ArduinoJson then receives a truncated or empty input and returns a parse error (`DeserializationError::IncompleteInput` or `NoMemory`). The firmware maps any parse error to `errorCode = -99` and sets `fetchFailed = true`.

This was observed on DUT when rapidly cycling StockApp chart range tabs: prior chart fetches fragment the heap; a subsequent `http.getString()` fails silently, producing the "NET ERR -99" display.

The alternative is to pass the HTTP stream directly:

```cpp
DeserializationError err = deserializeJson(doc, http.getStream());
```

ArduinoJson reads incrementally from the stream. The only allocation is the `DynamicJsonDocument` arena; no intermediate `String` is needed. This halves the peak heap pressure at parse time.

**Decision**:
Replace `deserializeJson(doc, http.getString())` with `deserializeJson(doc, http.getStream())`
in `fetchStockQuote()` and `fetchStockChart()` only. `fetchWeather()` and `fetchCrypto()` retain
`http.getString()` — see amendment below.

**Consequences**:
- Peak heap at parse time for stock fetches drops by (raw response size) — up to ~12 KB for 6M chart range
- `http.getString()` double-allocation failure path eliminated for the two Yahoo Finance endpoints
- The host budget check in `test_yahoo_finance_api.py` is now accurate: only `DynamicJsonDocument(N)` needs to fit for stock fetches
- Weather and crypto are unaffected — getString() continues to handle dechunking internally

**Amendment (2026-05-29 — VE challenge resolved)**:
Initial commit (4c3cb05) switched all four fetch functions to `getStream()`. VE challenge raised
same day: `feature_inventory.yaml` weather-001 documented `getString() required — chunked HTTPS
on Arduino-ESP32 2.0.17 fails deserializeJson on raw stream.` Host probe confirmed:
- `api.open-meteo.com` → `Transfer-Encoding: chunked`, no `Content-Length`
- `api.coingecko.com` → `Transfer-Encoding: chunked`, no `Content-Length`
- `query1.finance.yahoo.com` → `Content-Length` present, no chunked

`getStream()` on Arduino-ESP32 2.0.17 returns the raw `WiFiClientSecure` stream; the HTTPClient
does not dechunk it. ArduinoJson receives raw chunk-framing bytes and fails to parse JSON.
`fetchWeather()` and `fetchCrypto()` were reverted to `getString()` in the same session.
`fetchStockQuote()` and `fetchStockChart()` remain on `getStream()` — Yahoo Finance is safe.

**Supersedes**: none
