### ADR-034 — 2026-05-29 — dataTask HTTP response parsing shall use streaming, not buffered String accumulation

**Status**: accepted

**Context**:
All four fetch functions in `dataTaskStorage.cpp` (weather, crypto, stock quote, stock chart) follow the same pattern:

```cpp
DeserializationError err = deserializeJson(doc, http.getString());
```

`http.getString()` reads the full HTTP response body into a heap-allocated `String` before passing it to ArduinoJson. This means peak heap pressure at parse time is:

- raw response body (`String`) +
- `DynamicJsonDocument(N)` arena

Both allocations must succeed concurrently on the same heap. On a fragmented heap — which is normal after WiFi + TLS + multiple prior fetches — a `String` allocation for a >4 KB response can fail or return a truncated result. ArduinoJson then receives a truncated or empty input and returns a parse error (`DeserializationError::IncompleteInput` or `NoMemory`). The firmware maps any parse error to `errorCode = -99` and sets `fetchFailed = true`.

This was observed on DUT when rapidly cycling StockApp chart range tabs: prior chart fetches fragment the heap; a subsequent `http.getString()` fails silently, producing the "NET ERR -99" display.

The alternative is to pass the HTTP stream directly:

```cpp
DeserializationError err = deserializeJson(doc, http.getStream());
```

ArduinoJson reads incrementally from the stream. The only allocation is the `DynamicJsonDocument` arena; no intermediate `String` is needed. This halves the peak heap pressure at parse time.

**Decision**:
Replace `deserializeJson(doc, http.getString())` with `deserializeJson(doc, http.getStream())` in all four fetch functions. The stream must be consumed (or `http.end()` called) before the `HTTPClient` destructor runs — the existing `http.end()` calls already satisfy this. No other interface changes are required.

**Consequences**:
- Peak heap at parse time drops by (raw response size) per fetch — typically 2–12 KB depending on range
- `http.getString()` double-allocation failure path is eliminated
- The host budget check in `test_yahoo_finance_api.py` becomes more accurate: only `DynamicJsonDocument(N)` needs to fit, not `String + doc` combined
- Streaming parse is slightly slower (no read-ahead buffering beyond the TCP stack), but the HTTP round-trip already dominates latency
- ArduinoJson streaming from `WiFiClientSecure` is established practice; no new dependencies

**Supersedes**: none
