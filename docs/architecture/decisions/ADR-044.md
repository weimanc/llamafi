### ADR-044 — [2026-06-13] — M-TELETEXT: NOS Teletekst app architecture

**Status**: proposed

**Context**

A proof-of-concept for a live teletext reader was built and validated on-host
(2026-06-13). The NOS Teletekst API was reverse-engineered:

- URL: `https://teletekst-data.nos.nl/page/{page}` (no `.json` suffix)
- Response: ~1.1 KB, ISO-8859-1, page content in a `<pre>` block
- Format: exactly 1000 bytes = 25 rows × 40 columns, no newlines
- Control codes: 0x01–0x07 = Alpha (text mode, FG colour 1–7);
  0x10–0x17 = Mosaic (graphics mode, FG colour 0–7);
  0x1C = Black BG; 0x1D = New BG (copy FG→BG)
- Mosaic characters encode a 2×3 pixel grid; bit 5 is always 1 (keep printable):
  `pattern = (c&0x1F) | ((c&0x40)>>1)`
- Navigation metadata precedes the `<pre>` block:
  `pn=p_/n_/ns/ps` (prev/next page/subpage), `ftl=` (4 fast-text targets)
- Preview tool: `app/tools/preview_teletext.py` (full 320×240 canvas + taskbar,
  text/mosaic rendering, live navigation)

Resource impact is low (see design doc §DS-3 and §DS-4):
- Flash: ~6–8 KB app code + 1–2 KB root CA cert
- SRAM: ~4 KB persistent; TLS heap spike (~50–70 KB contiguous) is shared with
  the existing dataTask pattern, not additive
- Network: 1.1 KB per fetch; smallest payload of any API in the project

Four design questions were enumerated in `M-TELETEXT.md` with leans reached.

**Decision**

1. **App slot**: `Teletext` added to `appRegistry.h` as the 10th app (after
   `Aquarium`), with `configurable = 1`. Icon glyph: `T` pending a proper icon.

2. **Fetch architecture**: slot into `dataTask` as a new fetch type
   (`FETCH_TELETEXT_PAGE`). No new FreeRTOS task. Matches weather/crypto/stock
   pattern exactly.

3. **Canvas layout**: 6 × 8 px cells → 40 cols × 25 rows = 240 × 200 px.
   Remaining 35 px (between grid and taskbar) used as a **page-nav strip**:
   subpage-up arrow (top), current page number (middle), prev/next page arrows,
   subpage-down arrow (bottom). Arrows rendered as `fillTriangle()` calls —
   no additional font dependency.

4. **Bottom bar** (40 px): 4 fast-text coloured buttons (red/green/yellow/cyan)
   derived from `ftl=` metadata and row 24 label text. Mirrors the on-screen
   teletext remote-control buttons.

5. **Inline hyperlinks**: tap in the grid area → compute row; scan cols 35–39
   for a 3-digit page reference; if found, navigate and push previous page onto
   a 10-entry history ring (20 B on the app struct). 300 ms debounce.

6. **Settings** (`g_settings`, SPIFFS `/settings.json`):
   - `teletextPage` (`uint16_t`, default 101) — starting page on resume
   - `teletextPollSecs` (`uint8_t`, default 60) — refresh cadence: 30/60/120 s
   - `teletextCountry` (`uint8_t`, default 0 = NOS/NL) — reserved; single value
     until a multi-country R&D spike confirms compatible services
   - `teletextAutoAdvance` (`bool`, default false) — reserved; no Settings UI
     until subpage auto-advance is implemented; field present in struct from day 1
     to avoid a migration when the feature lands

7. **Multi-country**: deferred to R&D spike. `teletextCountry` field reserved
   in settings struct; Settings UI shows "NL (NOS)" as a non-interactive label
   until at least one second service is validated.

8. **TLS root CA**: confirmed via `openssl s_client` (2026-06-13).

   Chain: leaf (`CN=teletekst-data.nos.nl`) → Sectigo Public Server
   Authentication CA DV R36 (intermediate) → Sectigo Public Server
   Authentication Root R46 (cross-signed intermediate) →
   **USERTrust RSA Certification Authority** (self-signed root,
   valid 2010-02-01 – 2038-01-18).

   This is **not** DigiCert or ISRG. A new constant `TELETEXT_NOS_ROOT_CA`
   (USERTrust RSA Certification Authority PEM) is added to `dataTaskCerts.h`
   alongside the existing ISRG Root X1 entries.

   Rotation trigger:

   | Cert | Maintenance trigger | Action |
   |---|---|---|
   | USERTrust RSA Certification Authority | Expiry 2038-01-18 or Sectigo CA change | Update `TELETEXT_NOS_ROOT_CA` PEM in `dataTaskCerts.h`, reflash |

   Failure mode: TLS handshake failure logged as HTTP -1 by `dataTask`.
   Diagnose via `get teletextHttpCode` serial command (same pattern as
   `get cryptoHttpCode` per ADR-029).

9. **`tlsYield()` policy**: `fetchTeletext()` follows the **weather pattern**
   (no `spotifyTask::tlsYield()` / `tlsResume()` call). Teletext is
   weather-comparable in payload (1.1 KB, 30–120 s cadence, single GET).
   The TLS heap spike is transient and stack-allocated per fetch. Revisit
   if TLS heap pressure testing reveals contention with `spotifyTask`.

10. **UI iteration**: right-strip layout and inline hyperlink behaviour to be
    finalised in `preview_teletext.py` before any firmware is written.

**Consequences**

- `appRegistry.h` gains a 10th entry; `gen_app_registry.py` must be re-run;
  `run/check` gate [5/5] enforces staleness.
- `AppSettings` struct gains **four** fields (`teletextPage`, `teletextPollSecs`,
  `teletextCountry`, `teletextAutoAdvance`, ~5 B total). Fields are appended as a
  contiguous block at the end of the struct, after the Life block — consistent with
  the struct growth convention. SPIFFS JSON format extends with new named keys
  (backwards-compatible: defaults applied on missing keys).
- `dataTask` gains `FETCH_TELETEXT_PAGE` enum entry + `TeletextState` struct +
  `pollTeletext()` accessor — same extension pattern as weather/crypto/stock.
  `fetchTeletext()` does **not** call `tlsYield()` (weather pattern — see item 9).
- `dataTaskCerts.h` gains `TELETEXT_NOS_ROOT_CA` (USERTrust RSA CA PEM); see
  rotation trigger table in item 8. ADR-029 rotation table should be updated to
  include this endpoint.
- A teletext icon (`teletext.png` + `teletext_active.png`) must be sourced and
  baked via `run/bake-icons` before the taskbar slot is visible. The glyph
  character `'T'` is an acceptable permanent placeholder if a bespoke asset is
  not available before the first DUT flash.
- **Multi-country second entry is not a config-only change.** EXP-004 (2026-06-13)
  found that the only viable second service (SVT/SE via texttv.nu) requires: a
  separate JSON fetch sub-path inside `fetchTeletext()` branching on country, a
  new root CA cert for `texttv.nu` (to be verified), a UTF-8 parser branch (no
  0x01–0x17 control codes in SVT content), and a dedicated ADR before the Settings
  country selector is enabled. The `teletextCountry` enum is reserved but the UI
  remains non-interactive until that ADR is accepted.
- `preview_teletext.py` is the iteration surface for UI decisions — no firmware
  changes until the preview is signed off.
- **`architecture.md` update triggers** (post-acceptance): (1) add
  `teletekst-data.nos.nl` / USERTrust RSA CA to the TLS endpoint inventory;
  (2) document the `dataTask` pattern in the Data Flow section (currently
  Spotify-path only); (3) note `dataTaskCerts.h` as the cert registry for all
  non-Spotify HTTPS endpoints; (4) close the "TLS root CA for non-Spotify
  endpoints" open question with a reference to ADR-044.
