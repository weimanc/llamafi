# ADR-037 — Heatmap Tile Label: Graduated Font-Size Degradation

> Status: accepted
> Date: 2026-06-03

---

## Context

ADR-036 D6 specified a two-state tile label rule:
- Ticker symbol: always, Font 2 (16 px)
- Change %: only when `w ≥ 40 && h ≥ 28`, Font 1 (8 px)

This has two problems the user flagged:

1. **No graceful shrink.** There is no intermediate step between "full label" and "pct disappears". Tiles just below the 28 px threshold show a large ticker with no pct at all.
2. **Ticker can overflow.** Font 2 ticker is drawn unconditionally regardless of tile height. A tile with h=8 still attempts to draw 16 px text, overflowing into adjacent tiles.

User requirement: *"I rather shrink font sizes first before dropping the percentage, followed by dropping the ticker."*

---

## Available fonts on this DUT

Enabled build flags: `LOAD_FONT2`, `LOAD_FONT4`, `LOAD_FONT6`, `LOAD_FONT7`, `LOAD_FONT8`, `LOAD_GFXFF`.

| Font ID | Invocation | Cell height | Char width | Notes |
|---------|-----------|-------------|------------|-------|
| 1 | `drawString(..., 1)` | **8 px** | 6 px fixed (GLCD) | Smallest built-in |
| 2 | `drawString(..., 2)` | **16 px** | proportional 4–10 px | Current label font |
| 4 | `drawString(..., 4)` | 26 px | proportional | Too tall for most tiles |
| 6/7/8 | — | 48–75 px | — | Not applicable |
| GFX free fonts | `setFreeFont(...)` | 17+ px (yAdv) | proportional | Available but overlaps Font 2; no intermediate gain |

**Conclusion:** Only Font 1 (8 px) and Font 2 (16 px) are practically distinct for tile labels. GFX free fonts at 9 pt produce ≈17 px yAdvance — too close to Font 2 to add a useful intermediate step, and require additional `#include` and `setFreeFont` / `setTextFont` reset overhead. Design uses Font 1 and Font 2 exclusively.

### Measured character widths (Font 2, capital letters used in tickers)

```
A B C D E F G H J K L M N O P Q R S T U V W X Y Z  (px)
8 8 8 8 8 8 8 8 8 8 7 10 8 8 8 8 8 8 8 8 8 10 8 8 8
```

Worst-case 5-char ticker width (Font 2): "GOOGL" = 8+8+8+8+7 = **39 px**.  
Safe threshold for any ticker in Font 2: **w ≥ 40**.

Font 1 is fixed 6 px per character:
- 5-char ticker: 30 px
- 4-char ticker: 24 px
- 3-char ticker: 18 px

Pct string worst case `"+99.9%"` (6 chars):
- Font 1: 36 px
- Font 2: ≈ 50 px (too wide for small tiles)

---

## Decision

Replace the two-state label rule with a **5-tier cascade** evaluated top-to-bottom. Each tier specifies the full set of conditions, ticker font, pct font, and vertical positioning offsets from tile centre `cy`.

### Tier definitions

| Tier | Condition | Ticker | Pct | Notes |
|------|-----------|--------|-----|-------|
| 1 | `h ≥ 36 && w ≥ 40` | Font 2 | Font 2 | Both large |
| 2 | `h ≥ 28 && w ≥ 40` | Font 2 | Font 1 | Shrink pct font |
| 3 | `h ≥ 20 && w ≥ 40` | Font 1 | Font 1 | Shrink ticker font, keep pct |
| 4 | `h ≥ 18 && w ≥ 40` | Font 2 | — | Wide-short strip: F2 ticker only |
| 5 | `h ≥ 10 && w ≥ 20` | Font 1 | — | Narrow/short: F1 ticker only |
| 6 | else | — | — | Blank (colour-only tile) |

Evaluation is top-to-bottom; the **first matching tier wins**.

**Tier 3 precedes Tier 4** deliberately. At h=20–27 with w≥40 both would match if evaluated naively, but showing both strings at Font 1 is preferred over showing the ticker alone at Font 2 (honouring the user's "shrink font before dropping pct" requirement).

Tier 4 covers wide-but-short strips (e.g. h=18–19, w≥40) that fall out of Tier 3. A 16 px Font 2 string just fits in 18 px with no vertical padding. These are geometrically uncommon in a squarified treemap (near-square tiles dominate), but the tier exists to avoid falling back to 6 px text on a tile wide enough to render 16 px text.

Tier 5 (Font 1 ticker only) also serves as the **width-constrained fallback** for taller tiles whose width is in 20–39 px (too narrow for pct). Since Font 1 is 6 px fixed, a 5-char ticker is 30 px. For tickers shorter than `floor(w / 6)` chars the text fits; longer tickers **are silently skipped** (blank tile preferred over overflow into adjacent tiles). Check: `if (strlen(sym) * 6 > (size_t)t.w) skip`.

### Vertical positioning (with `MC_DATUM`)

TFT_eSPI `MC_DATUM` centres text around the given point `(cx, cy)` both horizontally and vertically. Two-line blocks are centered together around `cy`:

```
two-line centre offsets:
  line1_cy = cy - (h2 + gap) / 2
  line2_cy = cy + (h1 + gap) / 2
  (h1 = height of line 1 font, h2 = height of line 2 font, gap = 2)
```

| Tier | Ticker y | Pct y |
|------|----------|-------|
| 1 (F2+F2, gap=2) | `cy − 9` | `cy + 9` |
| 2 (F2+F1, gap=2) | `cy − 5` | `cy + 9` |
| 3 (F1+F1, gap=2) | `cy − 5` | `cy + 5` |
| 4 (F2 only) | `cy` | — |
| 5 (F1 only) | `cy` | — |

### Text overflow guard (Tier 5)

Before drawing in Tier 5, check ticker fits:
```cpp
if ((uint8_t)(strlen(sym) * 6) > t.w) return;   // skip: would overflow tile
```
No overflow guard is needed for Tiers 1–4 because `w ≥ 40` gates those tiers and the worst-case Font 2 ticker width is 39 px.

### Pct string format

Unchanged from ADR-036: `snprintf(pb, sizeof(pb), "%+.1f%%", pct)`.  
Max length: 7 chars (`"-99.9%"`). At Font 1 that is 42 px, safely within the w ≥ 40 guard in Tiers 1–3. (Font 2 pct in Tier 1 is ≈ 50 px; `w ≥ 40` is a necessary but not strictly sufficient guard. Tier 1 typically activates only on large-cap tiles where w >> 40, making clipping rare. If the pct string clips on a particularly narrow Tier 1 tile, the colour still conveys direction — acceptable.)

---

## Consequences

**Better:**
- No text overflow for short tiles (Font 2 ticker no longer drawn unconditionally)
- Pct is visible on more tiles (Font 1+Font 1 at h≥20 recovers tiles previously shown ticker-only)
- Degradation order matches user intent exactly

**Same:**
- Colour encoding is unchanged; information loss from blank tiles is unchanged
- No new fonts, no extra RAM, no extra `#include`

**Worse:**
- `repaintHeatmap()` gains ~30 lines of branching label logic
- Tier 3 / Tier 4 boundary (h=18–19 with w≥40) causes a non-monotonic font-size step: at h=19 the ticker is Font 2, at h=20 both lines are Font 1. Visual jump is real but localised to a 1-2 px height band; considered acceptable

Replaces the current label block in `repaintHeatmap()` (`main.cpp`). No changes to `computeHeatmapLayout()`, `HeatmapTile`, or data pipeline. Exit criterion: `check_build.sh` 4/4; visual verification on DUT showing all five tiers across a realistic 20-ticker heatmap.
