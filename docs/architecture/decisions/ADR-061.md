### ADR-061 — [2026-08-15] — Build-variant hygiene: debug/production separation, full-matrix gating, and dead-variant decommission

**Status**: proposed
**As-built**: 2026-08-15. Nothing in this ADR has been executed. The decommission
inventory (D6–D8) is a plan, not a record.

**Design doc**: [M-CODEQUAL-duplication-and-abstraction.md](../designs/M-CODEQUAL-duplication-and-abstraction.md) §5 (C4)

**Context**

Three problems share one root cause: **build variants and conditional compilation have no forcing
function.** Code that is not built does not rot loudly — it rots silently, and surfaces only when a
human reaches for it.

*1. The debug/production seam has no stated convention.* `app/src` carried **135**
conditional-compilation sites at the time of writing, **75 of them in `main.cpp`** — 56 % of the
firmware's total in one file. (M-SRCLAYOUT Stages A/B have since redistributed some of these across
`apps/` and `debug/serialConsole/`; the ratio, not the count, is the point.) Three mechanisms coexist: `#ifdef SERIAL_DEBUG` (the bulk, ~2 780 lines), `#ifdef
SD_BOOT_MOUNT` (a production-safe diagnostic subset), and `#ifdef MEMBUDGET_PHASE1`. The separation
is *reasoned* — the TASK-427 comments in `app/src/main.cpp` (`setup`, and the `sdMountAttempt()` /
`sdProbeBootMount()` block) explain precisely why the SD boot mount is gated on
`SD_BOOT_MOUNT` rather than `SERIAL_DEBUG` — but reasoned per-site, not by policy. The consequence is that
reading the production boot path means skipping 2 780 lines that never ship.

The correct pattern is **already in the tree, used once**: `app/src/main.cpp` (`mb_heap_probe`), where `mb_heap_probe()`
has a real body under `#ifdef` and a `static inline` no-op `#else`. Call sites stay unconditional and
the optimiser deletes them in release. It never became the convention.

*2. Five of eight build envs are ungated, and one has already rotted.* `platformio.ini` defines eight
envs; `check_build.sh` builds three (`cyd2usb_winamp`, `cyd2usb_winamp_debug`, `cyd2usb_player`). The
other five had **never been built on this machine** — no `.pio/build` directory existed for any of
them. Built on 2026-08-15 to test the hypothesis:

| env | result | cold build |
|---|---|---|
| `cyd2usb` | **FAIL** — `fatal error: JPEGDEC.h: No such file or directory` | 4 s |
| `cyd2usb_winamp_screenlog` | PASS | 18 s |
| `cyd2usb_webradio` | PASS | 15 s |
| `cyd2usb_webradio_16k` | PASS | 14 s |
| `cyd2usb_winamp_debug_noSpotify` | PASS | 15 s |

**The cost argument that produced the current gate is falsified by measurement.**
`check_build.sh:40-42` reads *"not a 2^3 matrix (eight full builds would make this gate unusable)"* —
the five ungated envs cold-built in **66 seconds total**.

*3. Rot is not only a compile problem.* Three further instances that building every env would **not**
catch:

- `run/ceefax-ws-soak:20` defaults `ENV_SPIKE` to `cyd2usb_winamp_debug_ceefaxspike`, an env deleted
  with the M-CEEFAX cut (ADR-058, commit `41448f5`). The script is permanently broken.
- Three `#ifdef SPIKE_MODE` blocks survive in `main.cpp` (`:209`, `:1257`, `:1681`) with no env in
  `app/platformio.ini` defining `SPIKE_MODE`. This code compiles cleanly in all eight envs *because
  it is never included in any of them* — the failure mode a build matrix is structurally blind to.
- `CLAUDE.md:122` says "other envs in `platformio.ini`: `cyd`, `trinity`" without naming which
  `platformio.ini`. Both exist — in `Spotify-Diy-Thing/platformio.ini:62,76`, the upstream project —
  but the surrounding text is about the app project, where neither does. Ambiguity, not falsehood;
  the fix is a reference, not a deletion.

The second bullet is the important one for scoping D6: **a full build matrix catches envs that stop
compiling, and nothing else.** Dead-but-valid `#ifdef` branches and stale cross-file references need
D7, which is why the two decisions travel together.

**Decision**

### Debug / production separation

**D1 — Production code contains no `#ifdef` for debug.** It calls a normally-named function. The
*implementation* is compiled out; the *interface* is not. The release build is a `static inline`
no-op, which the optimiser removes at zero cost. This generalises `mb_heap_probe()`
(`app/src/main.cpp`, `mb_heap_probe`) from a one-off into the house rule.

**D2 — Debug implementations live in `debug/` as components, never inline in the subsystem they
observe.** M-SRCLAYOUT Stage B relocated the bulk into `debug/serialConsole/*.h` (`b36f184`) but
produced **headers, not components** — they are not self-contained and are still `#include`d from
`main.cpp`'s `#ifdef SERIAL_DEBUG` block. Stage E (TASK-471) converts them to `.h`/`.cpp` pairs under
ADR-060 D0. D2 is satisfied only at that point; today it is half-done.

**D3 — Per-app introspection stays behind the existing `dbgGet`/`dbgSet` virtuals.** That contract
already does the right thing and is the model the shell-level debug surface should follow
(M-CODEQUAL C3).

**D4 — Production-safe, production-valuable diagnostics get their own feature gate and are not
lumped under `SERIAL_DEBUG`.** This is already the de facto rule — the SD boot mount and `wifiDiag`
both follow it — and D4 writes it down rather than inventing it.

**D5 — For small conditional blocks, prefer "always compile, never run" to `#ifdef`.** A
`const bool kDebug = false;` with a normal `if (kDebug)` keeps the body **type-checked** while the
compiler dead-code-eliminates it. This addresses a real failure mode: code inside `#ifdef` is not
compiled in production, so a rename breaks the debug build and nobody notices until someone flashes
debug firmware. Applies only where the referenced symbols still link in release; a 2 780-line console
is not a candidate. (`-std=gnu++11`, so plain `const bool` — `if constexpr` is C++17.)

### Build-matrix gating

**D6 — `run/check` builds every env in `platformio.ini`.** Measured cost for the five currently
ungated envs is 66 s. The gate's own stated objection is retired.

**D7 — A name-consistency gate accompanies it**, covering what D6 is structurally blind to. Three
checks, all greps, all costing milliseconds:

1. **Every env named in `run/*`, `check_build.sh`, `CLAUDE.md` and `docs/` exists in
   `app/platformio.ini`** — and every env in `app/platformio.ini` is either gated or explicitly
   declared non-building. Catches the `ceefax-ws-soak` instance.
2. **Every `#ifdef` flag in `app/src` is defined by at least one env** in `app/platformio.ini`, or is
   listed in an explicit allow-list of externally-supplied flags. Catches `SPIKE_MODE` — code that
   compiles cleanly everywhere precisely because it is compiled nowhere.
3. **Any reference to `platformio.ini` in prose names which one.** This repo holds two independent
   projects with overlapping env names (`cyd2usb` exists in both), so an unqualified reference is
   ambiguous by construction. Catches the `CLAUDE.md:122` instance.

Check 2 is the one with no existing analogue in the codebase and the one that pays for itself: it is
the only mechanism proposed here that finds *unreachable* conditional code, as opposed to *broken*
conditional code.

**D9 — `cheapYellowLCD.h` is NOT droppable in its current form, and no task may assume otherwise.**
Two hard dependencies from the *production* build:

1. **It owns the global TFT object.** `cheapYellowLCD.h:7` — `TFT_eSPI tft = TFT_eSPI();` — with
   **797 `tft.` call sites across 24 files**, the most-used symbol in the firmware, defined in an
   upstream compat header.
2. **`WinampDisplay` inherits from it.** `winamp/winampDisplay.h:169` —
   `class WinampDisplay : public CheapYellowDisplay`.

Note what is *already* resolved: `cheapYellowLCD.h:9` guards `#include <JPEGDEC.h>` behind
`#ifndef WINAMP_DISPLAY`, which is exactly why `cyd2usb` is the only failing env. What remains in a
Winamp build is not album-art code at all — it is the `tft` global plus a base class. TASK-062
(M-NOART, closed 2026-05-21) removed the album-art *path*; the file coupling was not in its scope and
is still open.

**Prerequisite chain, in order.** Each step is a **component** in ADR-060 D0's sense — `.h` declaring,
`.cpp` defining, header self-contained — not another header dropped into the tree:

1. **`display/tft.{h,cpp}`** — rehome the `TFT_eSPI tft` global. `extern TFT_eSPI tft;` in the header,
   the single definition in the `.cpp`. This is ADR-060 D2's composition-root problem one layer down:
   the most-used object in the firmware is currently constructed by an upstream compatibility header
   that nobody owns. It is a level-0/1 component under D2a, so nothing above it may be pulled in.
2. **`display/spotifyDisplay.h`** — confirm the abstract base is a clean D0 interface exception (pure
   virtual, no `.cpp`), as `app.h` is.
3. **Flatten `WinampDisplay` onto `SpotifyDisplay`**, absorbing what it actually uses from
   `CheapYellowDisplay`, and make `winamp/winampDisplay.{h,cpp}` a component in the same pass.
4. **Only then** delete `cheapYellowLCD.h`, and `[cyd2usb_base]` with it.

**Step 1 is worth doing regardless of whether the chain completes.** A single owned `display/tft`
component is strictly better than a global defined in vendored upstream compat code, even if
`cheapYellowLCD.h` never goes away.

D8's demotion of `cyd2usb` is deliberately independent of this chain — it retires the failing env
immediately whether or not step 3 ever happens.

**D10 — Vendored copies only.** These files exist twice: `app/lib/SpotifyDiyThingUpstream/` (what the
build uses) and `Spotify-Diy-Thing/SpotifyDiyThing/` (the upstream project, its own git repo). Only
the vendored copies are touched. `CLAUDE.md` is explicit that the upstream tree is a separate project.

**Consequences**

*Easier.* Production code becomes readable without mentally filtering `#ifdef` — the direct aim, given
`main.cpp` currently holds 56 % of the firmware's conditional compilation. Debug code stops rotting
invisibly: D6 makes it a build failure, D5 makes small blocks type-checked even in release. D7 closes
the class of rot that compiling cannot see. Retiring `cyd2usb` removes the firmware's only
album-art-path build and its orphaned `JPEGDEC` dependency.

*Harder.* `run/check` grows by ~66 s — acceptable for a pre-commit gate, but it is a real cost paid on
every invocation, and the number will grow with each new env. D1's no-op-inline discipline is
slightly more ceremony per debug hook than a bare `#ifdef`. D9's prerequisite chain means "delete
`cheapYellowLCD.h`" is three tasks, not one, and step 1 touches 797 call sites (mechanically, but
broadly).

*Constrained.* No new env may be added without being gated or explicitly declared non-building (D7).
The plain-CYD (`YELLOW_DISPLAY`, non-Winamp) and HUB75 (`MATRIX_DISPLAY`) display configurations are
**no longer supported targets** — human decision, 2026-08-15. `spotifyDisplay.h` stays: it is
`WinampDisplay`'s base and `main.cpp`'s `SpotifyDisplay*` handle.
