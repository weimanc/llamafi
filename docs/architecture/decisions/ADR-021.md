### ADR-021 — 2026-05-17 — Serial debug command framework (M-SERIALDBG)

**Status**: accepted (2026-05-17); amended (2026-05-17) — Decision 3 superseded by Amendment A1

**Context**:

M-SERIALDBG (roadmap 2026-05-17) expands `handleSerialCommands()` beyond the single `reconnect` command to support:
- Synthetic touch injection (`tap X Y`, `drag X1 Y1 X2 Y2 STEPS`)
- State interrogation (`get <var>`)
- State injection for test rig setup (`set <var> <val>`)
- General debug utilities (`info`, `help`)

This raised three architectural decisions:

1. **Command dispatch structure** — how commands are registered and dispatched.
2. **Response format** — how the firmware emits output that host scripts can parse.
3. **Internal state exposure** — whether task-internal variables are exposed via debug accessors, and how.
4. **Build env isolation** — whether `SERIAL_DEBUG` compiles into the standard env or a dedicated debug env.

The existing handler (`SpotifyDiyThing.ino:300`) is a single `strcmp` chain with a 32-byte line buffer. It does not scale past ~3 commands without becoming unmaintainable.

---

**Decision**

**1. Command dispatch: table-driven C dispatcher, no external library**

Replace the `strcmp` chain with a command table. Each row: `{const char *name, cmd_fn handler, const char *help}`. A `help` command auto-generates the command list from the table — the table is the single source of truth for command metadata. No YAML, no code-gen step, no build tool dependency.

Increase line buffer from 32 to 64 bytes to accommodate `drag X1 Y1 X2 Y2 STEPS` (worst case ~30 chars). Log a `WARN` if a received line hits the buffer ceiling — truncation is a documented limit, not a silent bug.

```c
typedef void (*cmd_fn)(const char *args);
struct SerialCmd { const char *name; cmd_fn fn; const char *help; };
static const SerialCmd kCmds[] = {
  { "reconnect", cmdReconnect, "TLS reset + force poll"             },
  { "tap",       cmdTap,       "tap <x> <y>"                        },
  { "drag",      cmdDrag,      "drag <x1> <y1> <x2> <y2> <steps>"  },
  { "get",       cmdGet,       "get <var>"                          },
  { "set",       cmdSet,       "set <var> <val>"                    },
  { "info",      cmdInfo,      "snapshot + backoff + heap summary"  },
  { "help",      cmdHelp,      "this message"                       },
};
```

**2. Response format: JSON lines**

All responses are one complete JSON object per `\n`. ArduinoJson is already in the tree; no new dependency. Host scripts use `json.loads(line)` — no regex fragility.

```
{"ok":true,"cmd":"tap","x":39,"y":175,"hit":"TRANSPORT","pressed":1,"action":"PLAY"}
{"ok":true,"cmd":"tap","x":0,"y":0,"hit":"NONE"}
{"ok":true,"cmd":"get","var":"snapshot","isPlaying":true,"progressMs":42000,"durationMs":210000,"volumePct":65,"shuffle":false,"repeat":2}
{"ok":true,"cmd":"get","var":"backoff","consecutiveFailures":3,"nextPollMs":40000}
{"ok":true,"cmd":"info","heap":180432,"isPlaying":true,"progressMs":42000,"consecutiveFailures":0}
{"ok":false,"cmd":"set","var":"foo","error":"unknown variable"}
{"ok":false,"cmd":"tap","error":"bad args"}
```

JSON response size limit: 256 bytes per line. Commands whose output would exceed this split into multiple lines (each a valid JSON object with a `"seq"` field) — required for `get snapshot` with long track/artist strings.

The `[serial-touch]` prefix notation in the test plan (T076–T082) is illustrative; actual output is the JSON format above. Test scripts check `ok`, `hit`, and `action` fields.

**3. Internal state exposure: narrow `#ifdef SERIAL_DEBUG` accessors**

`g_snapshot` is already extern + mux-protected — `cmdGet("snapshot")` calls the existing `copySnapshot()`. No new seam needed for reads.

Write access to task-internal state requires deliberate seams, declared in `spotifyTask.h` and `winampDisplay.h` inside `#ifdef SERIAL_DEBUG` guards:

```cpp
// spotifyTask.h
#ifdef SERIAL_DEBUG
namespace spotifyTask {
  void dbg_setFailureCount(unsigned int n);  // T079: force backoff state
  unsigned int dbg_getFailureCount();
}
#endif

// winampDisplay.h
#ifdef SERIAL_DEBUG
uint32_t dbg_getTouchCooldownRemainingMs();   // T079: verify cooldown gate
#endif
```

These are the only deliberate breaks of the "task owns its state" invariant. Kept minimal. `dbg_*` functions must only be called from the loop task (same thread as `handleSerialCommands`) — the same constraint that motivated spotifyTask isolation in the first place.

**4. Build env isolation: `cyd2usb_winamp_debug` only**

`SERIAL_DEBUG` is defined exclusively in a new `cyd2usb_winamp_debug` PlatformIO env. The standard `cyd2usb_winamp` env does NOT define it. Rationale: the debug command surface (`set backoff N`, `tap X Y`) is a test-rig capability, not a user-facing feature; shipping it in the default env widens attack surface and wastes flash.

The `reconnect` command (already in production) remains outside the `SERIAL_DEBUG` guard — it is a user-facing recovery tool, not a test-rig accessor. All new *commands* added under M-SERIALDBG are `SERIAL_DEBUG`-gated.

The boot version line (`[boot] git=... elf=... build=...`) is also unconditional — it ships in `cyd2usb_winamp` as well as the debug env. Rationale: it is a passive diagnostic, not a command surface; it adds no attack surface and its flash cost (one `Serial.printf` + `esp_app_get_description()` call) is negligible. It is carved out explicitly here alongside `reconnect` as a production-safe addition. The `GIT_REV` token within the boot line remains guarded (`#ifdef GIT_REV / #else "n/a"`) since that symbol is only defined in the debug env build.

`platformio.ini` diff:
```ini
[env:cyd2usb_winamp_debug]
extends = env:cyd2usb_winamp
build_flags =
  ${env:cyd2usb_winamp.build_flags}
  -DSERIAL_DEBUG
```

---

**Alternatives considered:**

**YAML → code-gen**: Define commands in a YAML file; Python generates both the C dispatch table and Python test stubs. Worthwhile at 30+ commands or with a CI harness; premature at current scale. Revisit if the command set grows or automated test execution is introduced.

**JSON-RPC both directions**: Host sends JSON, firmware parses it. 90% of the benefit with more framing complexity and an extra ArduinoJson parse on the receive path. Rejected: text commands in, JSON lines out is the right asymmetry for a serial debug interface.

**Arduino library (SimpleCLI, SerialCommands)**: Adds a transitive dep and PlatformIO pin discipline risk (same failure mode as the WiFi/Network split). Not worth it for ~10 commands.

---

**Consequences:**

What becomes easier:
- Adding a command: one table row + one function.
- `help` always reflects the actual command set — cannot drift.
- Host-side test scripts: `json.loads(line)` with field access, no regex.
- VE can construct deterministic test preconditions (e.g. `set backoff 5`) without waiting for real network failures.
- `SERIAL_DEBUG` compiles out completely in `cyd2usb_winamp` — zero flash/RAM overhead in production.

What becomes harder:
- Test sessions require flashing `cyd2usb_winamp_debug` instead of the default env — one extra flag.
- `winampDisplay` grows debug accessors, slightly coupling it to the debug layer.
- If YAML codegen is adopted later, table rows migrate to YAML — one-time cost.

What is constrained:
- Line buffer 64 bytes max. Truncation is warned, not silently eaten.
- `dbg_*` accessors: loop-task only. Cross-task calls are a latent mbedTLS race risk and are forbidden.
- JSON response ≤ 256 bytes per line; longer payloads must split across multiple JSON objects.
- `reconnect` is NOT `SERIAL_DEBUG`-gated — it ships in production. All M-SERIALDBG additions are gated.

**Design doc**: [M-SERIALDBG-serial-debug-framework.md](../designs/M-SERIALDBG-serial-debug-framework.md)

**Supersedes**: nothing. Closes the open question in M-SERIALDBG roadmap item (2026-05-17).

## Amendment A1 — 2026-05-17 — State exposure: owner-dispatch pattern

**Context**: sync-001 prerequisites (SERIALDBG-l, -m) require extending `get snapshot` with three new fields (`lastPollAgeMs`, `currentTrackUri`, `deviceActive`) and adding a new `get queue` command. Under the original Decision 3, both changes require editing `cmdGet` in `SpotifyDiyThing.ino` — a function that had already grown to know about every readable variable across two state owners. Each new domain or field extends the coupling. The pattern does not scale cleanly beyond the current scope.

Additionally, the original approach scattered individual `dbg_setFailureCount` / `dbg_getFailureCount` / `dbg_getTouchCooldownRemainingMs` functions across `spotifyTask.h` and `winampDisplay.h`, creating a fragmented per-field public surface that grows linearly with test requirements.

**Decision — supersedes Decision 3:**

**3 (revised). Internal state exposure: owner-dispatch via `IDebugExportable`**

State owners expose their debug surface through a unified two-method interface. `cmdGet` / `cmdSet` are dumb dispatchers that try each registered owner in order; they require no changes when new fields or domains are added.

**3a. New interface — `debugExportable.h`**

New file `SpotifyDiyThing/debugExportable.h` (compiled under `SERIAL_DEBUG` only):

```cpp
#pragma once
#ifdef SERIAL_DEBUG

class IDebugExportable {
public:
    // Serialize state for `var` into buf as JSON key-value fragment
    // (no outer braces). Returns false if var is unknown to this owner.
    // buf is null-terminated on success. Split protocol (multi-part)
    // is the implementer's responsibility for large payloads.
    virtual bool dbgGet(const char* var, char* buf, int len) const = 0;

    // Apply value for `var`. Returns false if var is unknown or val invalid.
    virtual bool dbgSet(const char* var, const char* val) = 0;

protected:
    ~IDebugExportable() = default;
};

#endif // SERIAL_DEBUG
```

**3b. `SpotifyDisplay` — default no-op implementation**

`spotifyDisplay.h` gains default no-ops under `SERIAL_DEBUG`; `WinampDisplay` overrides both:

```cpp
// spotifyDisplay.h — inside class SpotifyDisplay, SERIAL_DEBUG guard
#ifdef SERIAL_DEBUG
#include "debugExportable.h"
// SpotifyDisplay participates in the exporter protocol.
// Default: no-op (non-Winamp backends compile without change).
// WinampDisplay overrides both.
virtual bool dbgGet(const char* var, char* buf, int len) const { return false; }
virtual bool dbgSet(const char* var, const char* val) { return false; }
#endif
```

`WinampDisplay` replaces all scattered `dbg_*` methods with a single `dbgGet` / `dbgSet` override pair. Variables handled: `cooldown`, `dragState`, `optimisticVolume`, `songDuration`. No individual `dbg_getTouchCooldownRemainingMs` etc. in the public header — they are implementation details inside the override.

**3c. `spotifyTask` — unified namespace-level accessors**

`spotifyTask.h` exposes two functions under `SERIAL_DEBUG` in place of the previous per-field functions:

```cpp
// spotifyTask.h — SERIAL_DEBUG guard
#ifdef SERIAL_DEBUG
namespace spotifyTask {
    // Serialize state for var into buf. Returns false if var unknown.
    // Handles: "snapshot" (with lastPollAgeMs, currentTrackUri, deviceActive),
    //          "backoff", "queue". Split protocol for large payloads.
    bool dbg_get(const char* var, char* buf, int len);

    // Write a debug var. Returns false if var unknown.
    // Handles: "backoff" (sets consecutiveFailures).
    bool dbg_set(const char* var, const char* val);
}
#endif
```

`s_consecutiveFailures` remains `volatile`. `dbg_get("snapshot")` computes `lastPollAgeMs` inline (`millis() - snapshot.capturedAtMs`). `dbg_get("queue")` reads under `g_queueMux`. `dbg_get("backoff")` and `dbg_set("backoff", n)` replace `dbg_setFailureCount` / `dbg_getFailureCount` / `dbg_getNextWaitMs`.

**3d. `cmdGet` / `cmdSet` — dumb dispatchers**

```cpp
static void cmdGet(const char* args) {
#ifdef SERIAL_DEBUG
    char buf[256];
    // Try display owner first, then task owner.
    if ((spotifyDisplay && spotifyDisplay->dbgGet(args, buf, sizeof(buf)))
        || spotifyTask::dbg_get(args, buf, sizeof(buf))) {
        // buf already contains JSON fragments; wrap and emit.
        // Multi-part payloads: owner emits its own Serial.printf lines
        // and returns true; buf is empty string in that case.
        if (buf[0]) Serial.printf("{\"ok\":true,\"cmd\":\"get\",%s}\n", buf);
        return;
    }
    Serial.printf(
        "{\"ok\":false,\"cmd\":\"get\",\"error\":\"unknown var\",\"var\":\"%s\"}\n",
        args);
#endif
}

static void cmdSet(const char* args) {
#ifdef SERIAL_DEBUG
    char var[32]; char val[32];
    if (sscanf(args, "%31s %31s", var, val) != 2) {
        Serial.println("{\"ok\":false,\"cmd\":\"set\",\"error\":\"bad args\"}");
        return;
    }
    if ((spotifyDisplay && spotifyDisplay->dbgSet(var, val))
        || spotifyTask::dbg_set(var, val)) {
        Serial.printf("{\"ok\":true,\"cmd\":\"set\",\"var\":\"%s\",\"val\":\"%s\"}\n",
                      var, val);
        return;
    }
    Serial.printf(
        "{\"ok\":false,\"cmd\":\"set\",\"error\":\"unknown var\",\"var\":\"%s\"}\n",
        var);
#endif
}
```

`cmdGet` / `cmdSet` never need to change when new fields or domains are added — owners self-contain their variable space.

**Multi-part protocol for large payloads:** When a `dbg_get` implementation needs to emit more than 256 bytes (e.g. snapshot with long strings, queue rows), it emits its own `Serial.printf` lines directly and returns `true` with `buf[0] = '\0'`. `cmdGet` detects the empty buf and skips the wrapper print. The `"part":N` / `"last":true` convention from Feature 4 of the design doc applies unchanged — the owner is responsible for correct framing.

**3e. SERIALDBG-l and -m slot in without `cmdGet` changes**

- **SERIALDBG-l** (`lastPollAgeMs`, `currentTrackUri`, `deviceActive`): add `bool deviceActive` to `Snapshot`; populate in `onCurrentlyPlaying`; update `spotifyTask::dbg_get("snapshot")` to include the three fields in its serialization. `cmdGet` unchanged.
- **SERIALDBG-m** (`get queue`): add `"queue"` case to `spotifyTask::dbg_get`. `cmdGet` unchanged.

**Constraint unchanged from original Decision 3:** `dbg_get` / `dbg_set` / `dbgGet` / `dbgSet` must only be called from the loop task. Cross-task access is forbidden for the same reasons as the original — single aligned 32-bit stores are tolerated only where explicitly noted (see `resetBackoff()`).

---

**Amendment A1 — Consequences delta:**

Easier than before:
- Adding a new readable/writable field: edit the owning `dbg_get`/`dbg_set` or `dbgGet`/`dbgSet` only. `cmdGet`/`cmdSet` are frozen.
- TSYNC additions (SERIALDBG-l, -m) slot in without dispatcher changes.
- Public header surface shrinks: no more per-field `dbg_setFailureCount` / `dbg_getTouchCooldownRemainingMs` etc.

Harder than before:
- Multi-part serial emit responsibility moves from `cmdGet` to the owner — owner must correctly frame `"part"` / `"last"` lines.
- One new file (`debugExportable.h`); one new sub-task (SERIALDBG-n).

Constraints added:
- `WinampDisplay::dbgGet` / `WinampDisplay::dbgSet` must not call `ts.touched()` or any hardware peripheral — debug accessors read internal state only.
- `spotifyTask::dbg_get("queue")` must acquire `g_queueMux` (already required by `copyQueueSnapshot`).

**Design doc**: [M-SERIALDBG-serial-debug-framework.md](../designs/M-SERIALDBG-serial-debug-framework.md) — sub-tasks f, g, h revised; n added.
