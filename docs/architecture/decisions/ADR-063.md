### ADR-063 — [2026-09-04] — `App` gains a debug surface; identity and progress become shell facts

**Status**: accepted
**As-built**: not yet — this ADR authorises TASK-637 and TASK-593; neither has landed.
**Ruled**: human, 2026-09-04, on the Architect's decision A

**Requirement**: [R3](../../verification/M-HARNESS2-requirements.md), findings `A-8`, `G-3`, `B-5`
(WP-Z, [M-TESTQUAL-Z-findings-review.md](../../verification/reviews/M-TESTQUAL-Z-findings-review.md))

**Context**

The requirements document asks every app to publish four observables "through its `dbgGet` surface".
The seam it names does not exist. `app/src/app.h:11` declares the `App` interface — `init`, `resume`,
`suspend`, `tick`, `handleInput`, `hasPendingAsync` and the rest — and contains no `dbgGet` and no
`dbgSet`. The obligation lives in prose only, as a human checkbox at
`docs/architecture/designs/NEW-APP-CHECKLIST.md:89-93`, and `architecture.md:95-98` already *asserts*
the seam exists ("`+ dbgGet/dbgSet` (M-SERIALDBG)") against a header that does not have it — the
corpus has been describing a contract the code never carried.

Four of the thirteen apps have no override at all; their surfaces are typed branches in the console.
`app/src/debug/serialConsole/cmdGet.cpp:546` and `:554` reach into `g_ClockApp` directly, `:594` and
`:634-653` into `g_LocalPlayerApp`, `:424` into `g_WeatherApp`, `:429` into `g_CryptoApp`, `:459`
into `g_LifeApp`, `:703` into `g_SettingsApp`. `debug/` is level 2 and `apps/` is level 3 under
ADR-060 D2a, so **every one of those lines is an existing upward dependency**. Building R3's
conformance gate on top of them would have entrenched the violation rather than repaired it.

The defect R3(a) exists to fix is `A-8`: an app's keys answer *when the app is not active*, so a
`switchApp` that silently stopped switching fails no assertion anywhere. That is a property of the
console's dispatch, not of any app — and thirteen hand-written identity keys, each written by the
same author who wrote the app they are meant to police, fix it for none of the four apps that have no
`dbgGet` to put one in.

Cost is not the objection. The review priced the contract as written at ~120–150 B `.dram0.bss` and
8–12 KB debug flash, and as amended at ~60–110 B and ~4.5–5 KB (§2.2). The constraint is that
**every firmware obligation on this programme draws from one shared static-BSS pool** which has
measured 0 B, 40 B, 304 B and 9 920 B inside three months (§2.1), so the number is only ever valid
against a freshly derived `.map`.

**Decision**

**D1 — `App` gains two debug accessors, under `SERIAL_DEBUG`, with safe defaults.**

```
virtual bool dbgGet(const char* var, char* buf, int len) const { return false; }
virtual bool dbgSet(const char* var, const char* val)          { return false; }
```

Both non-pure, both defaulting to `false`, both compiled out entirely when `SERIAL_DEBUG` is not
defined (ADR-061 non-goal 6 — no debug obligation reaches a production build). The safe default is
what makes this landable without touching thirteen apps in one commit.

**D2 — the console delegates through `g_apps[]`, and the six typed instance names are deleted.**
`cmdGet.cpp` stops naming `g_ClockApp`, `g_WeatherApp`, `g_CryptoApp`, `g_LifeApp`,
`g_LocalPlayerApp` and `g_SettingsApp` and dispatches through the composition root's table
(`shell/appTable.h`, ADR-060 D2/D5). This is a level 2 → level 0 dependency in the console and level
3 → level 0 in each app: both downward. **The change removes a levelization violation; it does not
create one.**

*Note, not a licence:* `app/src/debug/serialConsole/cmdGet.cpp:703` also reads `g_settings`, the
settings **struct**, in the same line as `g_SettingsApp`. That is a different object, is not an app
instance, and D2 does not remove it.

**D3 — identity is a shell fact, published once, and enforced negatively.** R3(a) as an app
obligation is **rejected**. In its place: **a per-app key is refused with a named error when its
owning app is not the active app**, as one shared guard in the console's delegation path. The shell
already owns `currentAppId`; the contract is the *refusal*, not a re-publication. One generated
conformance row over `APP_ORDER` asserts it for all thirteen apps at once — "its keys answer while
active and refuse while not" — including the four with no `dbgGet` today.

**D4 — progress is a shell-owned counter array, not an app-owned counter.** Two `uint32_t` arrays
sized `APP_COUNT`, incremented by the shell around its own `appTick()` dispatch and around an
accepted repaint (the precedent is `get pleditRepaints`, ADR-059 D12). ~52 B each. A counter the app
increments in its own tick is a counter the app can be wrong about in exactly the way the test is
trying to detect; a counter the shell increments is one the app cannot fake.

**D5 — result and entry-state stay per-app, capped.** R3(c) and (d) are genuinely app-specific
(`G-3`: `get fetchErrorCode` does not exist; `B-5`: `stockMode` is settable but not gettable) and are
accepted unchanged, with an **ADR-060 D0a-style ceiling of 32 B `.dram0.bss` per app**, measured
against a `.map` re-derived immediately before each commit. The ceiling is deliberately low: it
forces reuse of fields that already exist rather than new state, which is what the requirement's own
costing assumed.

**D6 — landing order is fixed: shell half first, then one app per commit, never a sweep.** The shell
half (D3 + D4) is ~60 B and one commit and fixes `A-8` for all thirteen apps. If a freshly derived
`.dram0.bss` headroom reads under ~1 KB, **stop after the shell half** and ledger the per-app clauses
as dated `UNOBSERVABLE` rows.

**D7 — the contract is recorded in IFC-003.** `dbgGet`/`dbgSet` become message types D1/D2 on
IFC-003 with the active-app refusal as a numbered invariant, and `architecture.md:95-98` is corrected
in the same commit (it names `appShell.h`, which no longer holds the interface, and "IFC-002
(planned)", which is the wrong number — IFC-003 exists and is v1).

**Alternatives rejected**

| Alternative | Why not |
|---|---|
| Leave `dbgGet` as the checklist convention and gate on it | The gate can only assert what a generated enumeration reaches; today that is `cmdGet.cpp` by regex, which is why `check_app_conformance.py` carries a hand-edited `CMDGET` path constant. A gate over a convention with four known non-conformers is a gate that must ship with four exceptions. |
| Pure-virtual `dbgGet`, no default | Forces all thirteen apps in one commit, against a pool that has measured 0 B. D6 exists precisely to forbid that shape. |
| Thirteen app-authored identity keys (R3(a) as written) | Thirteen places for the same fact to be wrong, no cross-check, and no fix at all for the four apps with no `dbgGet`. Rejected. |
| App-owned progress counters | Not falsifiable by the party the test is auditing (D4). |
| A non-virtual registry of function pointers beside `g_apps[]` | Same dependency shape, one more mirror to keep in sync, and it cannot inherit the safe default. |

**Consequences**

- *Easier*: the console stops naming app instances, so `gen_get_keys.py` becomes correct by
  construction for the app half (it already sees `.cpp` bodies after TASK-600 — `gen_get_keys.py:48`
  globs `.h/.hpp/.cpp/.cc`, 43→111 keys). `A-8` becomes one generated conformance row.
- *Harder*: every new app now has a real interface obligation instead of a checkbox, and the
  conformance gate will fail a new app that declares a key it does not answer. That is the point.
- *Constrained*: the safe default means "returns false" is indistinguishable from "was never asked".
  **The conformance gate must therefore be generated over `APP_ORDER` × the app's *declared* keys,
  never over the presence of an override** — a gate that looks for an override reads a defaulting app
  as conformant.
- *Cost*: ~60 B `.dram0.bss` and ~300 B debug flash for the shell half; ~4 B RAM and ~150 B flash per
  per-app key thereafter. @Developer's own estimate for the whole of R3 is **7 days** (shell half
  ~1.5 d, thirteen apps at ~0.3 d, conformance rows ~1 d) — [Dev
  review](../designs/M-HARNESS2-DEV-review.md) row 3.
- *Constrained*: none of this exists in a production build, and none of it may be depended on by
  non-debug firmware.
