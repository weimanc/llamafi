### ADR-043 — [2026-06-12] — Per-app settings wiring: pull-on-resume + word-ID crypto

**Status**: accepted

**Context**

`AppSettings` in `settingsStorage.h` defines per-app preferences for five apps
(Matrix, Life, Aquarium, Stock, Crypto). The Settings UI (`AppsSection`) correctly
reads, cycles, and persists these fields. However, every app ignores `g_settings`
and uses hardcoded constants or defaults — the settings have no observable effect.

Three design problems required decisions before implementation:
1. **Activation model**: when do changed settings take effect?
2. **dataTask thread safety**: Stock and Crypto fetch on Core 0; `g_settings` lives
   on Core 1. How do configured symbols reach the fetch layer safely?
3. **Crypto coin identity**: CoinGecko API uses word IDs (`"bitcoin"`) not symbols
   (`"BTC"`). How is this bridged without a mapping table?

**Decision**

1. **Pull-on-resume** for all five apps. `App::resume()` reads `g_settings` into local
   behavioural state. Settings changes take effect on the next app activation — no
   restart required, no push/notification path added.

2. **Stock ticker entry pivoted to keyboard + online validation** (2026-06-12):
   Ticker rows in the Stock submenu open `KeyboardWidget` (`Mode::UpperAlpha`, max 7
   chars) instead of cycling from a pool. Typed symbol validated before saving via
   `enqueueStockChartBySym(sym, D1)` as oracle; `AppsSection::tick()` polls
   `pollStockChart()`; `ok && len > 0` → valid; error screen + tap-to-retry otherwise.
   20 s timeout. `SettingsApp::hasPendingAsync()` returns `true` during validation.
   `dataTask::configureStockTickers(tickers[8][8])` pushes confirmed tickers to Core 0
   under `s_spinlock`. `StockApp::resume()` re-fetches immediately when tickers changed.

3. **Word IDs stored directly** in `g_settings.cryptoCoins`. No symbol→ID mapping
   table. The IDs are the CoinGecko API keys; they are stored, cycled, and passed to
   `dataTask` as-is. A 12-entry inline `cgIdToDisplay()` lookup provides short
   display labels (`"bitcoin"→"BTC"`) for the CryptoApp screen and Settings UI.
   `cryptoCoins` field expanded from `[6][8]` to `[6][16]` to accommodate IDs up to
   13 characters (`"matic-network"`). SPIFFS JSON serialisation unaffected.

4. **Aquarium fish count** uses a runtime `_activeFish` counter in `AquariumApp`.
   Static pool remains max-size (16). All fish loops switch to `_activeFish`.
   Takes effect on `resume()` without a full `init()`.

**Consequences**

- Settings changes take effect on next app activation — consistent with the existing
  `resume()` lifecycle contract; no new inter-component coupling.
- `dataTask` API gains two configure functions; the existing spinlock covers them.
- `AppSettings` struct grows by ~48 bytes (crypto field expansion); SPIFFS JSON format
  is unaffected (named string fields).
- `formatCryptoPrice()` per-symbol logic replaced by magnitude heuristic (price < $1
  → 4 dp); works for any newly added coin without code changes.
- `MATRIX_TICK_MS` and `GOL_TICK_MS` compile-time constants replaced by per-instance
  `_tickMs` variables.
