### ADR-010 — 2026-05-07 — Logging redesign: esp_log + RAM ringbuffer + secret redactor

**Status**: accepted

**Context**:

DUT verification on 2026-05-07 (M3 Winamp display) exposed structural problems with how this firmware logs:

- Boot trace is lost when serial monitor attaches after boot.
- No levels, no tags — `Serial.println` ours, `SPOTIFY_DEBUG` from the vendored lib, system errors from Arduino-ESP32 all interleave with no filter.
- `configFile.h` still prints the parsed config JSON, which contains the refresh token and client secret. LL-002 / LL-003 fixed the vendored side but not ours.
- mbedTLS error codes (`0x0050`, `0x004C`, `-9984`, `-76`, `-80`) are opaque at the call site.
- TASK-014 (album-art hang) leaves no progress trail — `Removing existing image` then silence.
- No remote sink for headless / off-tether capture.

Whiteboard: `docs/architecture/whiteboards/2026-05-07-logging-rethink.md` — eight pain points and the design space (transport / buffering / remote sink / hygiene / decoder / traces / heartbeat). The whiteboard left four open questions; this ADR resolves them and locks tier-1 scope.

**Decisions**:

1. **Framework: ESP-IDF `esp_log`.** `ESP_LOGE/W/I/D/V(tag, fmt, …)`. Output funnels through `esp_log_set_vprintf(hook)` so we own a single fan-out point (Serial + RAM ringbuffer; Serial alone if buffer not yet initialised).
   *Why not a custom Serial macro layer*: `esp_log` is already in the build; ESP-IDF system errors (mbedTLS, lwip, wifi) already feed it, so adopting it pulls those into our pipeline at zero cost. A custom layer would have to either duplicate or ignore them.

2. **Migration policy: incremental.** New code uses `ESP_LOGx`. Existing `Serial.println` sites stay until touched, with **two carve-outs that are fixed in tier 1 regardless of policy** — the `configFile.h` JSON dump (secret leak) and any other call site found to print a token, Bearer header, or full URL with `client_id=…&client_secret=…`.

3. **Tag taxonomy: short, namespaced, lower-case dotted.**
   `wifi`, `wifi.dns`, `time`, `time.ntp`, `time.https`, `cfg`, `spotify`, `spotify.poll`, `spotify.tls`, `display`, `display.skin`, `nfc`, `drd`, `log` (meta).
   *Why dotted not flat*: parent prefix gives a coarse filter (`spotify.*` shuts up the whole subsystem at WARN) without an explicit hierarchy table. esp_log already supports per-tag levels; the dotted form is just a naming convention.

4. **Default levels at boot:**
   - `INFO` baseline.
   - `DEBUG` for `display`, `spotify`, `time` while M3/M5/time work is active. Lifted to `INFO` once those subsystems stabilise (revisit per milestone).
   - `WARN` for tags we don't own (vendored: `HTTPClient`, `WiFiClient`, `ssl_client`, `mbedtls`).
   - All overridable at runtime via `esp_log_level_set` — exposed in tier 2 over the `/log` endpoint.

5. **RAM ringbuffer: 12 KB, line-oriented, drop-oldest.**
   Backed by a fixed `static char` buffer guarded by a `portMUX_TYPE` spinlock. Each line is null-terminated; the writer wraps and overwrites. ~120 lines @ 100 chars average. *Why 12 KB*: 8 KB drops too much when verbose tags are on; 16 KB starts to bite into heap on low-memory paths. 12 KB is the round-number compromise; revisit if heap-low warnings surface.

6. **Pull endpoint `/log` on the device's existing web server (refreshToken page).**
   `GET /log?n=80` returns the last N lines as `text/plain`. `GET /log?clear=1` empties the ringbuffer. Cheap, pull-not-push, no always-on listener required on the host. **No auth** — the device only serves on its LAN IP, and there's nothing here that wasn't already on Serial. Document that.

7. **mbedTLS / HTTP code decoder.** Small static table covering the codes we've actually hit:
   `0x0050` NET_CONN_RESET, `0x004C` NET_RECV_FAILED, `-9984` X509_CERT_VERIFY_FAILED, `-76` UNKNOWN_HOST, `-80` SSL_HANDSHAKE_FAILED, plus HTTP 401/403/429/5xx with their canonical reason. `LOG_TLS_ERR(rc)` and `LOG_HTTP_ERR(code)` macros. Unknown codes pass through as raw hex/integer — no silent loss.

8. **Secret redactor.** Lives in `secret.h` next to `configFile.h`, exposed as a single helper:
   `redact(const char *secret) -> "AQ…IY (len=131)"` — first two and last two chars plus length. Banned at review: printing config JSON, Bearer headers, query strings containing `client_secret=`. Tier-1 work removes the `configFile.h` dump in the same commit that introduces the helper.

9. **Heartbeat.** A 30 s tick at INFO with one structured line:
   `hb display=winamp wifi=rssi(-58) heap=128k poll=ok(204):42/last=200 uptime=00:42:18`
   Single tag `hb`. Key=value pairs, machine-greppable. Counters reset on reboot.

**What is in tier 1 (this ADR's scope)**:

1–9 above, in roughly this order:
- (a) `esp_log` hook + ringbuffer + `/log` endpoint.
- (b) `secret.h` + remove `configFile.h` JSON dump.
- (c) Decoder macros + first set of call-site adoptions in `spotifyLogic.h` and the TLS retry paths.
- (d) Heartbeat task.

**Out of scope for this ADR (deferred to ADR-011 if it materialises)**:

- UDP syslog push (`R1` in the whiteboard).
- State-machine trace points beyond what call-site migration naturally produces.
- SPIFFS-backed ringbuffer + panic-handler flush.
- Per-tag level control via web UI or serial command.

These all build on the tier-1 surface — none of them need to be re-thought when picked up.

**Consequences**:

- *Easier*: any future "what was the device doing 30 s ago" answers from a `curl http://<ip>/log` instead of "hope you had the monitor attached". mbedTLS / HTTP errors readable at the call site. No more "did we just leak the refresh token again" anxiety in commits.
- *Harder*: anyone adding a `Serial.println` now has to know about the migration policy. Mitigation: lint via review + grep in CI when CI exists.
- *Cost*: ringbuffer eats 12 KB SRAM permanently (we have ~250 KB free heap typical, comfortable). `esp_log_set_vprintf` adds a few hundred bytes of code. Heartbeat adds one task or one super-loop tick — single-digit µs per cycle.
- *Constrained*: log lines that exceed the ringbuffer line cap (256 chars) are truncated with `…` — long URL dumps cannot fit. Acceptable; truncation is loud, not silent.

**Open** (deferred, not blocking):

- Whether the heartbeat should be a FreeRTOS task or a super-loop tick. Lean: super-loop tick, keeps the existing single-task structure.
- Format of the `/log` endpoint: plain text vs. NDJSON. Lean: plain text — `curl | grep` is the dominant use case.
- Whether to expose the build epoch / commit short-sha in heartbeat. Lean: yes, in tier 1.

**Amendments — 2026-05-07 (post multi-role review, see `ADR-010-review.md`)**:

- Spinlock kind: `portENTER_CRITICAL_SAFE` / `portEXIT_CRITICAL_SAFE` (works in both task and ISR context). Decision 5 updated.
- HTTP server: tier 1 must stand up a **permanent post-connect HTTP server** (not the portal/refreshToken-only one) bound explicitly to `WiFi.localIP()`. The `/log` endpoint is mounted there. Decision 6 updated.
- Line-cap behaviour: when a log line exceeds 256 chars and is truncated with "…", emit a one-time WARN tagged `log` so silent truncation is impossible.
- Audit script (`tools/audit_log_hygiene.sh`): grep for banned patterns (`Bearer `, `client_secret=`, `Serial.print*` of names matching `*token*`/`*secret*`/`*refresh*`). Required for tier 1; tracked as TASK-016e.
- Process: ADRs require @VE testability + @Developer implementability passes before transitioning to `accepted`. ADR-010 reached `accepted` ahead of this review and was amended retroactively; this is QM's promotion candidate (LL-010 follow-up), awaiting human approval.

**Amendments — 2026-05-07 (post tier-1 DUT verification)**:

Three findings from running tier 1 on hardware. None invalidate the design; all are corrections to the *mental model*.

1. **`CORE_DEBUG_LEVEL` is a build-time gate, not runtime.** Arduino-ESP32 strips `ESP_LOGI/D/V` calls at compile time when `CORE_DEBUG_LEVEL` is below the corresponding level. The runtime `esp_log_level_set()` cannot bring back what wasn't compiled in. Tier 1 requires `-DCORE_DEBUG_LEVEL=3` (Info) at minimum — added to the `cyd2usb` env. Without it, "log sink up", heartbeats, and every other `ESP_LOGI` are silently no-ops.

2. **`esp_log_level_set("tag", LEVEL)` is exact-tag, not prefix-match.** The whiteboard's dotted-prefix mental model ("`spotify.*` shuts up the whole subsystem at WARN") is wrong about behavior. Setting `"spotify"` to DEBUG affects only the literal tag `"spotify"` — `"spotify.poll"` is still governed by the `"*"` baseline. **WARN/ERROR cross-tag still work** because the baseline is INFO and WARN/ERROR are above it; only DEBUG/VERBOSE are filtered without an explicit per-subtag override. We keep the dotted naming for grep readability, but we no longer claim it's a hierarchical filter. **Convention going forward (TASK-016f, 2026-05-07):** every dotted subtag is registered explicitly in `logsink::begin()` next to its parent. Adding a new `ESP_LOGD("foo.bar", …)` site means adding `esp_log_level_set("foo.bar", ESP_LOG_DEBUG)` in `begin()`.

3. **Arduino-ESP32 `log_e`/`log_w` macros bypass `esp_log`.** The `[E][ssl_client.cpp:37] _handle_error()` lines that come from Arduino-ESP32's own `log_e` macro print directly via `Serial.printf`/`printf`, not through `esp_log_writev`. They appear in serial but **do not reach our `vprintfHook` and so are NOT captured in the ringbuffer**. Tier-1 ringbuffer capture is therefore partial — system tags from ESP-IDF proper (mbedtls internals, lwip, wifi events) flow through; Arduino-ESP32's own `log_*` macros do not. **Capturing those is explicitly tier-2 scope** — a redirect of `Serial` itself, or a wrapper that intercepts `printf`, would be required and is too invasive for this milestone.

**Amendments — 2026-05-07 (post TASK-018 DUT verify, blast-radius correction)**:

The amendment-3 finding above ("Arduino-ESP32 `log_e`/`log_w` bypass `esp_log`") was correct but **misunderstood in scope**. Caught during TASK-018 (M-LOG2) integration: even our own `ESP_LOGI/W/D/E` calls bypass our `vprintfHook`. Arduino-ESP32 ships `<esp32-hal-log.h>` which **redefines** the `ESP_LOGx` macros to expand to its Arduino-side `log_x` (lower-case) macros — those go through `printf`, not `esp_log_writev`. So the bypass is total: no `ESP_LOGx` call from any TU compiled against Arduino-ESP32 reaches our hook.

Diagnostic that nailed it on DUT: `g_head` and `g_count` stayed at 0 across many seconds while dozens of `[I][...]` formatted lines streamed past on Serial — only consistent if the formatted lines never touched `ringPush`.

**Resolution**: tier-1 logging adds a thin `LOG_I/W/D/E(tag, fmt, ...)` macro layer in `logSink.h` that formats once, writes the formatted line to Serial, and calls `ringPush` directly — bypassing both Arduino-ESP32's `log_x` macros and ESP-IDF's `esp_log_writev`. Migration: any call site whose lines we want in the ringbuffer must use `LOG_x`, not `ESP_LOGx`. Existing `ESP_LOGx` call sites still work (output to Serial via Arduino's macros) but won't appear in `/log` or the on-screen overlay. Migrate as needed.

`esp_log_set_vprintf` is kept — it still catches whatever ESP-IDF code actually uses `esp_log_writev` (mbedtls internals, lwip events, etc.), so those continue to flow into the ring even though Arduino-ESP32's macros don't.

Live DUT verification completed for: `secret.h` redactor pool (8-slot rotating buffer needed — single-buffer aliased all `redact()` args in one printf to the last-written value); ESP_LOGI captured by hook; heartbeat tick fires (loop-tick gated, blocks during long network retries — surfaces opaque blocking, intended); WARN-level `spotify.poll` tag visible.

Live verification deferred: `/log` HTTP endpoint (Marriott guest WiFi has client-isolation on; host cannot reach `172.20.1.42`; works in code, not network-testable from this LAN).
