### ADR-018 — 2026-05-15 — M-LIST-v2 — Winamp PLEDIT playlist skin

**Status**: accepted with Amendment 1 (2026-05-15 — original acceptance; Amendment 1 same day corrects PLEDIT.BMP sprite positions, row count, and removes erroneous row-highlight sprite after Audacious source review).

---

## Context

TASK-020 landed the M-LIST proof-of-concept (DUT-verified 2026-05-15): a 320×124 strip below the Winamp chrome showing 7 rows of queue data using TFT_eSPI Font 2, black background, yellow row 0, grey-green rows 1-6. Functional but visually plain — resembles a debug list rather than a Winamp playlist panel.

The user wants the strip to look like Winamp's **Playlist Editor** (`PLEDIT.BMP`). Same bake-then-render pipeline as the main chrome (ADR-003, ADR-014).

Available panel area: **320 × 124 px** at `y = 116..240` (landscape, `originY = 0`).

Full `PLEDIT.BMP` is 275 × 232 px — taller than the panel. A fitting strategy is required.

---

## Fitting Strategy — Option C chosen

Four options were evaluated:

| Option | Description |
|---|---|
| A | Track-list only — PLEDIT row bg colour + highlight sprite, no chrome bars |
| **C (chosen)** | PLEDIT hybrid — bake title bar (~14 px) + bottom bar (~20 px) + row highlight; track list in between |
| B | Full PLEDIT window cropped/stretched into 320×124 |
| D | Colour palette only — no new sprites |

**Decision: Option C.**

Rationale: visual authenticity was the stated priority. The PLEDIT title bar and bottom button bar are the strongest identity signals of the Winamp playlist editor. Option C delivers them within the flash budget without destroying row count entirely. Option B requires stretching a 275 px-wide asset to 320 px (12 % horizontal scale artefact) and leaves only ~90 px for track rows. Option A and D are improvements but don't read as "Winamp playlist."

## Layout (post-Option-C)

```
y=116 ┌────────────────────────────────┐  ← PLEDIT_Y
      │  [PLEDIT title bar, 14 px]     │  ← baked into SKIN_PLEDIT_BG (static)
y=130 ├────────────────────────────────┤  ← PLEDIT_ROWS_Y
      │  row 0 — currently playing     │  ← SKIN_PLEDIT_ROW_HIGHLIGHT + white text
y=146 ├────────────────────────────────┤
      │  row 1 — queue[0]              │  ← PLEDIT row bg colour + PLEDIT_FG colour
y=162 ├────────────────────────────────┤
      │  row 2 — queue[1]              │
y=178 ├────────────────────────────────┤
      │  row 3 — queue[2]              │
y=194 ├────────────────────────────────┤
      │  row 4 — queue[3]              │
y=210 ├────────────────────────────────┤
      │  row 5 — queue[4]              │
y=224 ├────────────────────────────────┤  ← PLEDIT_BOTTOM_Y (computed: 116+14+5*16=224)
      │  [PLEDIT bottom bar, 16 px]    │  ← baked into SKIN_PLEDIT_BG (static)
y=240 └────────────────────────────────┘
```

`124 − 14 (title) − 16 (bottom) = 94 px ÷ 16 px/row = 5 rows` (with 14 px residual — absorb into bottom bar height or pad below row 5 as inert bg).

**Row count: 5.** Row 0 = currently-playing; rows 1-4 = next-up queue. `QUEUE_MAX` drops from 7 to 5 (save ~290 bytes RAM).

## Row text format

```
[nn.] Artist - Title            MM:SS
```

- Left-aligned: track index (`"1."`, `"2."` etc.) + `" "` + `artist + " - " + name`, truncated with `…` to fit.
- Right-aligned: `MM:SS` from `durationMs`. Field width: 5 chars (`"00:00"` up to `"99:59"`).
- Available chars: `320 px / ~7 px per char at Font 2 ≈ 45 chars` total. Duration field + 1 space = 6 chars right side; title field ≈ 39 chars.
- Font: TFT_eSPI **Font 2** (unchanged from TASK-020).

Row 0 differs:
- Text colour: white `0xFFFF` on PLEDIT highlight bg.
- Leading `►` or index `"0."` — to be decided at impl time; `►` matches Winamp's playing indicator.

## New API data: duration_ms

`QueueEntry` currently stores `name[48]`, `artist[32]`, `uri[64]`. Add:

```cpp
struct QueueEntry {
  char     name[48];
  char     artist[32];
  char     uri[64];       // tier-2 tap-to-play
  uint32_t durationMs;    // NEW — for MM:SS display and total time
};
```

`getQueue()` ArduinoJson filter doc already parses `name`/`artists`/`uri`; extend to also extract `duration_ms` from both `currently_playing` and `queue[]` items.

`currently_playing.duration_ms` is already on the existing `Snapshot` (used for posbar). Mirror it into `QueueEntry[0].durationMs` at snapshot-write time — no extra API call.

## Flash budget

Only the baked portions of PLEDIT.BMP are stored:

| Asset | Size estimate |
|---|---|
| `SKIN_PLEDIT_BG` (320×30 composite — title + bottom bars) | `320 × 30 × 2 = 19 200 bytes` (~19 KB) |
| `SKIN_PLEDIT_ROW_HIGHLIGHT` (260×16 from PLEDIT.BMP inner track) | `260 × 16 × 2 = 8 320 bytes` (~8 KB) |
| Total new flash | **~27 KB** |

Current state: ~49.9 % of 2.56 MB app0 used. 27 KB = ~1 % additional. Well within budget.

Actual sprite dimensions subject to inspection of `base-2.91.wsz/PLEDIT.BMP` at bake time. Record empirically in `bake_skin.py` comments (LL-016 pattern).

## Bake-tool changes (TASK-047a)

New function `build_pledit_atlas(wsz)` in `tools/bake_skin.py`:

1. Extract `PLEDIT.BMP` from the `.wsz` archive (same `zipfile` pattern as existing sheets).
2. Inspect dimensions + pixel layout empirically; record in comments.
3. Crop title bar strip: `(0, 0, 275, 14)` — scale to 320 px wide (or centre + pad black).
4. Crop bottom bar strip: `(0, bottom_y, 275, 16)` — same horizontal treatment.
5. Composite both into a single `SKIN_PLEDIT_BG[320 * 30]` array (title at top, bottom bar at bottom of the array, 0-indexed; renderer uses offset arithmetic).
6. Crop row-highlight sprite: `(0, first_row_y, 260, 16)` → `SKIN_PLEDIT_ROW_HIGHLIGHT[260 * 16]`.
7. Emit all three to `gen/skin_assets.c`; emit layout constants to `gen/skin_layout.h`.
8. Composite into `gen/skin_preview.png` lower band with 5 sample rows.

The 275 px → 320 px horizontal fit for the title and bottom bars:
- **Prefer: pad with PLEDIT body background colour** (typically black `0x0e0e0e`) on right. Avoids stretch artefacts. Confirm the body bg colour from PLEDIT pixel scan.
- Fallback: stretch (nearest-neighbour) if pad looks wrong — decide at bake time.

## Total time display

The PLEDIT bottom bar in Winamp shows total playlist time. Sum of `durationMs` across all snapshot entries.

- Tier 1: render `"X:XX:XX"` (hours:minutes:seconds) at the PLEDIT bottom bar time slot using Font 1 (fits the smaller bottom bar). Position to be derived from PLEDIT.BMP inspection.
- This is the only dynamic element in the bottom bar. All buttons (ADD/REM/SEL/MISC/LIST) are static decoration.

## Amendment 1 — 2026-05-15 — PLEDIT.BMP sprite correction

**Trigger:** TASK-047a baked PLEDIT strips using empirical y-offsets derived from cyan separator pixels. Post-bake review confirmed this approach was wrong. Audacious source (`skin.cc`, `playlist-widget.cc`, `playlistwin.cc`) provides authoritative sprite coordinates.

**Reference:** `docs/rnd/resources/winamp-skin-format/PLEDIT-BMP-spec.md`

### §A1 — Corrected PLEDIT.BMP sprite positions

Audacious `skin_draw_playlistwin_frame()` hardcodes these y offsets:

| Band | y start | height | Content |
|---|---|---|---|
| Title focused | 0 | 20 px | `(0,0,25,20)` left · `(26,0,100,20)` centre · `(153,0,25,20)` right |
| Title unfocused | 21 | 20 px | Same x layout, y=21 |
| Frame sides | 42 | 29 px | Left tile `(0,42,12,29)` · Right tile `(32,42,19,29)` |
| **Bottom bar** | **72** | **38 px** | Left/menu `(0,72,125,38)` · Right/buttons `(126,72,150,38)` |

**What TASK-047a got wrong:**

| Element | 047a crop | Correct crop | Error |
|---|---|---|---|
| Bottom bar | y=111..128, 18px | **y=72..109, 38px** | Off by 39px; used extra button-state rows |
| "Row highlight" | y=42..55, 14px | **does not exist** | y=42 is the frame-sides band, not a row sprite |

**Cyan separators at y=20,41,71,110…** are skin-artwork palette pixels at band boundaries. Winamp ignores them and uses hardcoded offsets. They must not be used as structural delimiters.

### §A2 — Row rendering: no BMP sprite

`playlist-widget.cc` draws rows entirely with flat `fillRect` + text:

- Normal row bg: `cairo_paint` with `SKIN_PLEDIT_NORMALBG` (`#000000` from this skin).
- Selected row bg: `cairo_rectangle` + `cairo_fill` with `SKIN_PLEDIT_SELECTEDBG` (`#0000C6`).
- Text: `SKIN_PLEDIT_NORMAL` (`#00FF00`) / `SKIN_PLEDIT_CURRENT` (`#FFFFFF`).
- **PLEDIT.BMP is never blitted for individual rows.**

`SKIN_PLEDIT_ROW_HIGHLIGHT` emitted by TASK-047a commit `949c057` is incorrect and must be removed.

### §A3 — Updated geometry and row count

Window overhead: `20 (title) + 38 (bottom) = 58 px`.
Panel available: 320×124 at y=116..240.
Row area: `124 − 58 = 66 px`.
Row height (Font 2 char height): **16 px**.
Row count: `floor(66 / 16) = 4` (not 5 — original estimate assumed wrong overhead).

Updated layout:

```
y=116 ┌────────────────────────────────┐  PLEDIT_Y
      │  title bar, 20 px             │  y=116..135
y=136 ├────────────────────────────────┤  PLEDIT_ROWS_Y
      │  row 0 — currently playing    │  fillRect PLEDIT_BG_SELECTED
y=152 ├────────────────────────────────┤
      │  row 1 — queue[0]             │  fillRect PLEDIT_BG_NORMAL (black)
y=168 ├────────────────────────────────┤
      │  row 2 — queue[1]             │
y=184 ├────────────────────────────────┤
      │  row 3 — queue[2]             │
y=200 ├────────────────────────────────┤  PLEDIT_BOTTOM_Y
      │  bottom bar, 38 px (→ y=237) │  y=200..237
y=238 │  (2 px body-bg gap)           │
y=240 └────────────────────────────────┘
```

### §A4 — Updated layout constants (supersede §A3 of original ADR)

```c
#define PLEDIT_Y          116
#define PLEDIT_H          124
#define PLEDIT_W          320
#define PLEDIT_TITLE_H     20   // confirmed empirical + Audacious (y=0..19)
#define PLEDIT_BOTTOM_H    38   // corrected (was 18); Audacious y=72..109
#define PLEDIT_ROWS_Y     136   // PLEDIT_Y + PLEDIT_TITLE_H
#define PLEDIT_ROW_H       16   // Font 2 char height; Winamp is font-driven
#define PLEDIT_ROW_COUNT    4   // corrected (was 5); 66px / 16px = 4
#define PLEDIT_BOTTOM_Y   200   // PLEDIT_ROWS_Y + ROW_COUNT * ROW_H
// PLEDIT_LEFT_PAD  = 12  (left side-tile width — informational, not blitted in tier 1)
// PLEDIT_RIGHT_PAD = 19  (right side-tile width — informational, not blitted in tier 1)
```

Side tiles (left 12px, right 19px from y=42..70) are **deferred to Tier 2** — blitting them requires tiling 29px sprites across 66px of row height per row, adding complexity. The track list text will start at `x=0` in Tier 1.

### §A5 — Updated SKIN_PLEDIT_BG atlas

| Old (047a) | New (Amendment 1) |
|---|---|
| 320×38 (title 20px + bottom 18px) | **320×58 (title 20px + bottom 38px)** |
| Bottom crop: y=111..128 | **Bottom crop: y=72..109** |

`SKIN_PLEDIT_ROW_HIGHLIGHT` (260×14): **removed**. No equivalent in Winamp.

Flash delta: 320×58×2 = 37,120 bytes (~36 KB) for BG alone. Previous: 24,320 + 7,280 = 31,600 bytes. Net increase ~5.5 KB. Still within ADR-018 flash budget.
