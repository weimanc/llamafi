### ADR-041 — [2026-06-06] — X-macro app registry as single source of truth for app ordering and enablement

**Status**: proposed

**Context**

App identity (name, enum value, taskbar icon, configurability) is currently
scattered across five files:

| File | What it repeats |
|------|----------------|
| `appShell.h` | `AppId` enum (order and numeric values) |
| `taskbar.h` | `icons[]` — must match enum order exactly |
| `main.cpp` | `g_apps[]` dispatch table — must match enum order |
| `settings/appsSection.h` | Hardcoded 5-app configurable list (Stock, Crypto, Aquarium, Matrix, Life) |
| `tools/run_serialdbg_tests.py` | `_STOCK_APP_ID = 7`, `_SPOTIFY_APP_ID = 0`, `_switch_to(dut,"Matrix",4)`, etc. |
| `tools/test_tls_yield_reliability.py` | `_WEATHER_APP_ID = 2`, `_CRYPTO_APP_ID = 3`, etc. |

There is no way to disable an app without touching all six sites, and no way
to reorder apps without a multi-file audit. Any omission (e.g., adding an app
to `AppId` but not `icons[]`) is a silent runtime bug.

**Decision**

Introduce a single X-macro table file (`app/src/appRegistry.h`) as the
authoritative definition of every app's identity: name, icon glyph,
configurable flag, and order. All six sites above are reduced to a mechanical
expansion of this table.

A small Python codegen script (`app/tools/gen_app_registry.py`) parses
`appRegistry.h` and emits `app/tools/app_ids_gen.py` — the Python-side
mirror used by the test suite. The script is run on demand (not a PIO
pre-build hook) and its output is checked into git. CI (or a pre-commit note)
reminds the developer to re-run it after touching `appRegistry.h`.

**Rejected alternatives**

- *Python-first registry (Option B):* Registry lives in `.py`, codegen writes
  a C header. Inverts the dependency; the canonical representation should be in
  the build language (C), not the test language.

- *Manually-synced Python constants (Option C):* No automation; the same
  drift problem we have today, slightly easier to update.

- *Template metaprogramming / constexpr arrays:* Overkill, doesn't help the
  Python test side.

**Consequences**

- Adding an app = one new line in `appRegistry.h` + re-run codegen.
- Removing/disabling an app = comment out that line + re-run codegen.
- Enum values shift when apps are removed — the serial `switchApp <N>` debug
  command is affected, but tests migrate to `switchApp <name>` (see
  M-APP-REGISTRY design doc).
- `appsSection.h` no longer has a hardcoded configurable-app list; it expands
  the X-macro filtered on the `CONFIGURABLE` flag.
- `taskbar.h` `icons[]` is generated from the macro — order stays correct
  automatically.
- `check_build.sh` golden hash will change after the refactor (expected, update
  it as part of the implementation commit).
